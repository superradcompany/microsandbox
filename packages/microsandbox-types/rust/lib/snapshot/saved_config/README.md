# Saved configuration implementation notes

This is an internal PR3 implementation stage, not an enabled capture or restore feature. The approved contract is `planning/microsandbox/todo/lifecycle-saved-config-design.md`. The complete PR must implement that contract's other policy families, capture provenance and exclusions, mode-specific resolution, destination binding enforcement, CLI/SDK controls and live qualification before advertising `microsandbox.sandbox-config` in `SUPPORTED_REQUIRES`. No existing writer, descriptor reader, launch protocol or persisted sandbox configuration is changed by this module.

## Runtime representation

The runtime section has a closed field inventory: workdir, shell, entrypoint, cmd, env, scripts, init, hostname, user and guest clock. Invocation, logging, metrics configuration, host paths, credentials and arbitrary operational fields are not runtime fallback fields. Resources, labels, guest security, lifetime, binding inventory, provenance and pending configuration now have separate typed sections described below. Storage/IPC requirements are described below; authoritative full-state resource identity and remaining provenance families still need integration. Portable network records are described below.

Each field distinguishes absence from `{ "state": "default" }`, `{ "state": "unknown", "reason": "not_recorded" }`, and `{ "state": "value", "value": ..., "origin": "configured" }`. Unknown reasons are closed (`not_recorded`, `not_observed`, `converging`), and origins are closed (`configured`, `image`, `platform`, `observed`). Origins describe evidence; they are never authorization or archive-selected reuse policy. Present null is invalid. Explicit empty argv/maps and false/zero in applicable typed fields remain values.

Command/init text has either a literal value or a logical binding ID. Ordinary declared literal values are preserved exactly, including empty text; typed secret capture and exclusion are separate prerequisites and must not be inferred from variable names. A binding cannot contain a resolved value. Script bodies retain exact normalized UTF-8 content, permission bits and a SHA-256 digest, or a logical binding with neither content nor hash. Scripts are data to reconstruct, never restore hooks. Full-state script handle/backing compatibility remains an additional activation gate; matching this digest alone does not establish it.

Init distinguishes a known builtin choice from unknown history. A handoff records original auto/path selection, the observed absolute guest executable, arguments and init environment. Saved auto does not rerun discovery. Generated versus explicit hostname is retained as a separate tagged choice. Relative guest command workdirs and shell names preserve existing command lookup semantics; these are not host paths.

`binding_requirements()` derives potential consumers from actual typed references. Init uses imply `BootInit`; entrypoint/CMD/env uses imply `NewCommand`; script references imply `ScriptBacking`. Shared IDs retain every consumer. This is not a resolver or a readiness decision: resolution must first apply mode, clears and overrides, validate the inventory, combine gateway/captured-execution requirements and enforce the resulting immediate/deferred demands. An artifact-supplied consumer claim cannot downgrade an actual init use to a future command.

## Network representation and secret projection

The network section records ordered policy, DNS/TLS/secret policy, connection and queue caps, rate-limit parameters, NAT64 prefixes, guest services, logical trust requirements, denial-response settings and proxy protocol intent. It has no endpoint, host-port, CA path, private-key, proxy-password or host secret-source fields. These resources use logical destination references. Recorded interface allocation identity belongs to separate capture provenance and authoritative full-state metadata, not a reusable destination allocation default. Cache capacity/validity are destination tuning/provenance; generated certificates and private cache state are not exported as launch defaults.

| Current source fields | Portable treatment |
| --- | --- |
| `enabled`, `policy`, `strict`, `nat64_prefixes` | Explicit policy data; ordered rules are preserved. |
| `dns` | Protection and timeout settings plus destination resolver references. Empty references use destination discovery. |
| `tls` | Policy and logical trust bindings; no cert/key paths or generated cache. |
| `secrets` | Placeholder identity, allowed hosts, substitution and violation policy with a destination binding per secret. |
| Connection caps, accept queue, rate limiter, `http` | Typed tuning, preserving zero-as-unlimited and empty-message semantics. |
| `ports` | Guest service plus logical listener binding. Identity is binding plus protocol: different host listeners may forward to the same guest port. |
| `trust_host_cas` | Guest trust requirements with destination bindings; no automatic source-host CA lookup. |
| `outbound_proxy` | Protocol plus separate endpoint/credential references; missing requirements must not become direct routing. |
| `interface` | Separate captured identity/provenance; never source allocation authority in this reusable section. |

`SavedSecretsConfig::from_source()` is the first explicit capture projection. It exhaustively destructures existing secret types, copies only the policy fields and requires a caller-selected destination binding for every secret. It neither reads nor clones the resolved value or host-side source. Missing/misspelled mappings and duplicate identities fail without echoing source values; diagnostics can identify the affected entry by index. This helper does not yet implement full sandbox capture exclusions, literal-env provenance or binding activation. Synthetic sentinel tests cover both a resolved credential and a distinct host source-variable name.

`SavedDnsConfig`, `SavedTlsConfig`, `SavedProxy` and `SavedPublishedPort` also provide explicit `from_source()` projections. Resolver and trust replacement lists must match the source inventory exactly and retain its order; proxy credential bindings must match the source authentication mode, including an empty-but-present SOCKS4 identity. TLS interception requires a logical identity binding even when its CA was generated rather than configured by path. Source resolver/proxy addresses, listener ownership, usernames, password sources, certificate/key paths and certificate-cache state never become portable values. Disabled safeguards and policy ordering remain recorded facts, not destination approval.

These helpers accept source settings obtained under the caller's capture guard. They do not establish active/last-active provenance, observe resolved CA identity, open source files, obtain credentials or perform full-resume backing checks. The complete document must still validate binding kinds across families, and capture exclusions still apply to ordinary policy text. They do not enable snapshot writing or activation; runtime retention, coherent capture, exclusions and the complete consumer paths remain required.

Saved disabled safeguards remain recorded rather than silently rewritten. Parsing a false rebind/verification setting or a bypass rule is not consent to apply it: the resolver must still demand relevant explicit destination approval, enforce mandatory policy and establish gateway/captured-connection compatibility before execution. The document now validates the binding inventory, but these types still do not enable the resolver or activation.

## Document, resources and execution policy

`SavedSandboxConfig` carries `schema_version: 1`, `active`, `bindings`, `provenance`, and optional `pending`. Each active/pending record currently contains resources, runtime, network, execution and storage sections. This is still an internal incomplete schema: expanded placement/network identity provenance and authoritative full-state checks must be completed before writing artifacts. Unknown versions, extra operational fields, duplicate keys and present null values fail. The whole document, including pending/provenance, shares the byte/depth/map bounds; the script budget is combined across active and pending.

Resource records separate CPU/memory allocation, maxima and THP. Zero allocation/maxima and concrete allocation greater than its maximum fail. Active concrete CPU/memory values require observed origin; requested values can appear in pending intent, never promoted into confirmed active capacity. Missing/default/unknown observations retain their distinction. A recorded generation must be observed or explicitly unknown, but the capture path must still prove coherence; an origin tag is not evidence by itself. Full resume must also validate the existing authoritative checkpoint geometry and backing.

Execution defaults carry user labels, the guest security profile, sandbox-wide rlimits and duration policy. They exclude one-command invocation limits, elapsed counters, ephemeral ownership and destination deployment/placement choices. `SavedLifetimePolicy::from_source()` explicitly projects only durations and never copies ephemeral consent. Saved security settings still require destination constraints and approval checks in the resolver. Capture must distinguish user labels from regenerated system/artifact labels and apply exclusion controls.

Rlimits and lifetime durations use `SavedU64`, encoded as canonical unsigned decimal strings. This preserves the existing entire `u64` range, including the unlimited rlimit sentinel, without violating the descriptor's JSON-safe numeric bound. Numeric JSON, signs, exponents, leading zeros and overflow reject. Duplicate rlimit resources and soft greater than hard reject. The tests round-trip every existing resource kind and boundary quantities through the actual descriptor canonical JSON writer. This encoding affects only the new internal extension types; existing SDK/wire encodings are unchanged.

The binding inventory declares destination value shapes, not credential values, source lookup instructions or activation timing. Consumers are derived from runtime and network fields. Shared IDs retain all consumers, so a future-command use cannot weaken a gateway or init requirement. Compatible certificate uses can share a binding; incompatible destination shapes cannot. Missing, wrong-kind and unreferenced entries reject. Pending references are checked against the inventory but `active_binding_uses()` deliberately excludes their consumers. The resolver must recompute demand after saved/fresh selection, clears and explicit overrides; this method alone cannot authorize launch or deferred exec.

`validate_legacy_projections()` checks duplicated user/clock records against the released extensions, without changing their serialization or registering a manifest reader. Conflicting concrete values or unknown/default claims that disagree with an existing legacy projection fail with redacted field diagnostics. The same explicit projection check now also validates owned references against existing authoritative owned-storage records. Runtime checkpoint geometry and full resource identity still require activation integration.

## Storage and IPC representation

The storage section retains canonical guest mount targets, resource kinds, mount flags, guest ownership, filesystem metadata policy, quota/capacity and logical destination bindings. Bind files and directories are distinct observed kinds. Named storage records its observed directory/disk kind rather than guessing from a source volume name or transient create/ensure intent. External disk images retain format and optional guest filesystem type. Tmpfs retains capacity/options without claiming that a disk snapshot includes its transient contents. Root layout remains in the existing authoritative artifact metadata.

Owned mounts contain only guest path and the existing mount ID. Their options, backing closure and layout remain in `microsandbox.owned-volumes`, with no duplicate mutable copy in saved config. A concrete saved mount list must reference that complete inventory exactly; replacing an owned target with an external mount or omitting its reference rejects. Unknown or absent saved lists do not erase existing authoritative owned requirements. Validation includes a real collision fixture for the existing 32-bit mount-ID suffix: distinct guest paths that hash to the same ID must not alias one backing. This adds no new ID format or migration.

Guest paths use the existing cross-platform Unix normalizer, but archive input must already be canonical; it is not silently repaired. Mounts require the existing parent-before-child ordering and unique guest paths. Kind-specific ownership/metadata checks follow existing SDK rules. Recorded mirroring, symlink-following and other relaxations remain data, not destination permission. Full resume must still match authoritative captured handles/resources; equal path/options/content do not prove identity.

Vsock records guest port, stream/datagram type and a logical destination endpoint. Port zero/wildcard and datagram clock port 123 reject, and identity is type plus port. Stream and datagram routes can use the same number. Destination platform and deployment constraints remain activation checks; no unsupported host endpoint is silently substituted. Mount and IPC references join the document's typed binding inventory, including cross-family collision checks. Pending routes validate but never enter active demand.

`SavedMount::from_source()` and `SavedVsockRoute::from_source()` exhaustively project source fields without reading or cloning host paths, source volume names, creation directives or socket paths. The caller must provide logical bindings and guarded observed bind/named backing evidence. Missing or wrong-kind evidence refuses instead of consulting source paths or guessing. Owned options/backing are obtained from the authoritative existing inventory. These helpers do not yet connect capture, prove coherent resource identity, materialize resources or authorize activation.

## Draft bounds and diagnostics

These internal limits are explicit, tested and subject to the complete schema's milestone-1 review before exposure. Encoded saved config is bounded to 512 KiB within the descriptor's existing 1 MiB limit; maps/argument lists to 256 entries; nesting to 24 levels; each inline script to 64 KiB and all inline scripts to 256 KiB. Logical binding IDs use at most 128 ASCII alphanumeric, dot, underscore or hyphen bytes. Names are bounded to 256 UTF-8 bytes. Text arguments/env values are bounded to 64 KiB and exclude NUL; guest command settings/user/init paths are bounded to 4096 bytes. Script names must be a single component; destination-specific filename restrictions still need enforcement before host materialization. Permission bits exclude setuid, setgid, sticky and object-type bits.

Decode rejects duplicate keys before typed conversion and unknown fields at every operational record, including empty variants. All numbers must remain exact JSON-safe integers, matching descriptor canonicalization; typed construction is checked too. Serde internally tagged unit variants do not reject additional fields, so the empty default/builtin variants deliberately use strict empty struct variants. Existing `SnapshotManifestError::ManifestParse` carries `SCFG_JSON`, `SCFG_SCHEMA`, `SCFG_LIMIT`, `SCFG_VALUE`, `SCFG_BINDING`, `SCFG_IDENTITY` or `SCFG_INTEGRITY` plus a field path and safe explanation. Rejected values and unknown keys are not echoed. Debug output for saved values hides literal content and binding IDs. The complete descriptor boundary must preserve this redaction behavior too.

## Capture-time runtime exclusions

`apply_runtime_capture_controls` consumes a local typed capture draft and applies the caller's structural selectors to both active and pending runtime sections before serialization or size validation. Ordinary declared literals remain eligible for export; this is neither secret discovery nor permission to copy a raw local configuration. Known credential/resource projection, source provenance, coherent generation and actual script backing remain prerequisites. The controls do not run on imported artifacts or enable extension emission.

Optional runtime fields and exact environment/script keys may be omitted. Individual entrypoint/CMD/init arguments and init environment inputs require logical text bindings instead of positional deletion or silently dropping required init input. Full-state capture refuses omission of scripts, init, hostname and clock; script content can be replaced with a binding, with captured backing compatibility still required later. Binding a script replaces its entire inline representation, leaving no source content, mode or digest. Keys containing dots remain literal keys. A selector must match active or pending input; overlapping whole-field/key selectors and incompatible binding kinds refuse with value-safe diagnostics. The CLI/SDK parser and complete cross-family capture controls remain unfinished.

Binding inventories are recomputed across all active and pending consumers. A runtime exclusion cannot remove a shared gateway, storage or init requirement. Only displaced declarations are pruned; unrelated unused or malformed declarations still fail final validation. Pending-only bindings remain metadata rather than active demand, and unknown active fields never borrow pending values. No raw source configuration, filesystem access, runtime mutation or destination authorization is performed by this layer.
