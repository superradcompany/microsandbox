ESLint plugins are JavaScript loaded into the linter process. Prepare the dependency tree in one sandbox, snapshot it, then run the plugin against read-only source with no network access.

This recipe assumes the current project has `package.json`, `package-lock.json`, `eslint.config.js`, and a `src` directory.

## Prepare the linter

```sh
msb run --name eslint-base --replace \
  --memory 768M --root-disk 2G --max-duration 5m \
  --copy-file ./package.json:/workspace/package.json \
  --copy-file ./package-lock.json:/workspace/package-lock.json \
  --copy-file ./eslint.config.js:/workspace/eslint.config.js \
  --workdir /workspace \
  node:22.23.2-bookworm-slim -- sh -lc \
    'npm ci --ignore-scripts && chown -R node:node /workspace && install -d -o node -g node /workspace/src'

msb snapshot create eslint-runtime \
  --from eslint-base --integrity --force
msb snapshot verify eslint-runtime
```

`--ignore-scripts` blocks install hooks. It does not make the plugin safe to execute; loading the plugin is the step isolated below.

## Lint offline

```sh
msb run --name eslint-check --replace \
  --from-snapshot eslint-runtime \
  --mount-dir ./src:/workspace/src:ro \
  --workdir /workspace --user node \
  --cpus 1 --memory 384M --max-duration 1m \
  --no-net --security restricted \
  --rlimit nproc=64 --rlimit nofile=128 \
  -- npx --offline eslint src
```

The plugin can read the prepared configuration, dependencies, and mounted source, but it cannot modify `src` or reach the network. ESLint's exit code returns directly to the host.

Mount only the files the linter needs. For example, add a read-only `tsconfig.json` with `--mount-file` instead of mounting the whole checkout.

<Warning>
  Review and pin the lockfile before preparing the snapshot. Do not place registry credentials, source code, or secrets in a reusable snapshot.
</Warning>

## Cleanup

```sh
msb rm -f eslint-base eslint-check
msb snapshot remove eslint-runtime
```
