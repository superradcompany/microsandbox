<Tooltip tip="Outbound proxies are not yet available on microsandbox cloud."><span className="msb-badge-local">Local-only <Icon icon="circle-info" size={11} /></span></Tooltip>

Configure one HTTP CONNECT, SOCKS4, or SOCKS5 proxy for outbound sandbox traffic. The guest connects to its normal destination; microsandbox routes eligible traffic through the proxy on the host.

Set `sandbox_defaults.outbound_proxy` in [global configuration](/configuration#sandbox_defaults) for a shared default. Administrators can enforce or clear it through [managed configuration](/enterprise/corporate-networking#route-sandbox-traffic), which takes precedence over per-sandbox CLI and SDK options.

## Supported proxies

| Proxy | Authentication | Traffic | Availability |
|-------|----------------|---------|--------------|
| HTTP CONNECT | Optional username and password | TCP | SDKs and CLI |
| SOCKS4 | None | TCP | SDKs and CLI |
| SOCKS4 | Optional user ID | TCP | SDKs and CLI |
| SOCKS5 | None | TCP and non-DNS UDP | SDKs and CLI |
| SOCKS5 | Optional username and password | TCP and non-DNS UDP | SDKs and CLI |

You can configure only one proxy for a sandbox. A SOCKS4 user ID identifies the caller; it is not a password.

## Configure a proxy

<CodeGroup>
```typescript TypeScript
import { Sandbox } from "microsandbox";

await using sb = await Sandbox.builder("proxied")
  .image("python")
  .proxy((p) => p.socks5("127.0.0.1:1080"))
  .create();
```

```rust Rust
use microsandbox::Sandbox;

let sb = Sandbox::builder("proxied")
    .image("python")
    .proxy(|p| p.socks5("127.0.0.1:1080"))
    .create()
    .await?;
```

```python Python
from microsandbox import OutboundProxy, Sandbox

sb = await Sandbox.create(
    "proxied",
    image="python",
    proxy=OutboundProxy.socks5("127.0.0.1:1080"),
)
```

```go Go
sb, err := m.CreateSandbox(ctx, "proxied",
    m.WithImage("python"),
    m.WithProxy(m.SOCKS5Proxy("127.0.0.1:1080")),
)
```

```ruby Ruby
sb = Microsandbox::Sandbox.create(
  "proxied",
  image: "python",
  proxy: Microsandbox::OutboundProxy.socks5("127.0.0.1:1080")
)
```

```bash CLI
# Choose one:
msb create python --name proxied --proxy http://127.0.0.1:3128
msb create python --name proxied --proxy socks4://127.0.0.1:1080
msb create python --name proxied --proxy socks5://127.0.0.1:1080
```
</CodeGroup>

SDK addresses use `IP:port`. The `msb run` and `msb create` commands accept `--proxy http://IP:port`, `socks4://IP:port`, or `socks5://IP:port`. Proxy URIs reject user information, paths, query parameters, and fragments; SOCKS authentication uses separate CLI flags.

## HTTP CONNECT

HTTP CONNECT opens a TCP tunnel through an HTTP proxy. It supports optional HTTP Basic authentication and TCP only; UDP is unsupported. microsandbox resolves and checks the destination using its normal DNS and egress policy before sending the destination IP and port in the CONNECT request. The proxy address itself must be an IP address with a port.

The selected `msb` runtime must support HTTP CONNECT. When using an older runtime, the SDK requests an upgrade before creating or replacing a sandbox.

<CodeGroup>
```typescript TypeScript
.proxy((p) => p.httpConnect("127.0.0.1:3128"))
```

```rust Rust
.proxy(|p| p.http_connect("127.0.0.1:3128"))
```

```python Python
proxy=OutboundProxy.http_connect("127.0.0.1:3128")
```

```go Go
m.WithProxy(m.HTTPConnectProxy("127.0.0.1:3128"))
```

```ruby Ruby
proxy = Microsandbox::OutboundProxy.http_connect("127.0.0.1:3128")
sandbox = Microsandbox::Sandbox.create("proxied", image: "alpine", proxy: proxy)
```

```bash CLI
msb run alpine --proxy http://127.0.0.1:3128
```
</CodeGroup>

## SOCKS4 user ID

Add an optional user ID through an SDK or `--socks4-user-id` in the CLI.

<CodeGroup>
```typescript TypeScript
.proxy((p) => p.socks4("127.0.0.1:1080").userId("sandbox"))
```

```rust Rust
.proxy(|p| p.socks4("127.0.0.1:1080").user_id("sandbox"))
```

```python Python
proxy=OutboundProxy.socks4("127.0.0.1:1080", user_id="sandbox")
```

```go Go
m.WithProxy(m.SOCKS4Proxy(
    "127.0.0.1:1080",
    m.SOCKS4ProxyOptions{UserID: "sandbox"},
))
```

```ruby Ruby
proxy = Microsandbox::OutboundProxy.socks4("127.0.0.1:1080").user_id("sandbox")
```

```bash CLI
msb run alpine \
  --proxy socks4://127.0.0.1:1080 \
  --socks4-user-id sandbox
```
</CodeGroup>

The user ID must contain 1–255 bytes and cannot contain a null byte. Omit it to use SOCKS4 without a user ID.

## SOCKS5 credentials

SOCKS5 supports optional username/password authentication. Passwords are loaded from a host environment variable rather than placed directly in configuration.

<CodeGroup>
```typescript TypeScript
.proxy((proxy) =>
  proxy.socks5("127.0.0.1:1080").credentials(
    "sandbox",
    SecretSource.env("SOCKS5_PASSWORD"),
  ),
)
```

```rust Rust
.proxy(|proxy| {
    proxy.socks5("127.0.0.1:1080").credentials(
        "sandbox",
        SecretSource::env("SOCKS5_PASSWORD"),
    )
})
```

```python Python
proxy = OutboundProxy.socks5("127.0.0.1:1080").credentials(
    "sandbox",
    SecretSource.env("SOCKS5_PASSWORD"),
)
```

```go Go
proxy := m.SOCKS5Proxy("127.0.0.1:1080").Credentials(
    "sandbox",
    m.SecretSourceEnv("SOCKS5_PASSWORD"),
)
m.WithProxy(proxy)
```

```ruby Ruby
proxy = Microsandbox::OutboundProxy.socks5("127.0.0.1:1080").credentials(
  "sandbox",
  Microsandbox::SecretSource.env("SOCKS5_PASSWORD")
)
```

```bash CLI
msb run alpine \
  --proxy socks5://127.0.0.1:1080 \
  --socks5-username sandbox \
  --socks5-password-env SOCKS5_PASSWORD
```
</CodeGroup>

- **Password source:** Set the password in a host environment variable, the only supported source. Configuration stores only the variable name, such as `SOCKS5_PASSWORD`, never the password.
- **When changes apply:** The password is read when the sandbox starts. Restart the sandbox after changing it.
- **Requirements:** The username and password must each contain 1–255 bytes. Startup fails if the password variable is missing, empty, or invalid.

<Warning>
  SOCKS5 authentication does not encrypt credentials in transit. Use a trusted local or private proxy, or encrypt the connection separately.
</Warning>

## HTTP CONNECT credentials

HTTP CONNECT supports optional HTTP Basic authentication. Passwords are loaded from a host environment variable rather than placed directly in configuration.

<CodeGroup>
```typescript TypeScript
.proxy((proxy) =>
  proxy.httpConnect("127.0.0.1:3128").credentials(
    "sandbox",
    SecretSource.env("HTTP_CONNECT_PASSWORD"),
  ),
)
```

```rust Rust
.proxy(|proxy| {
    proxy.http_connect("127.0.0.1:3128").credentials(
        "sandbox",
        SecretSource::env("HTTP_CONNECT_PASSWORD"),
    )
})
```

```python Python
proxy = OutboundProxy.http_connect("127.0.0.1:3128").credentials(
    "sandbox",
    SecretSource.env("HTTP_CONNECT_PASSWORD"),
)
```

```go Go
proxy := m.HTTPConnectProxy("127.0.0.1:3128").Credentials(
    "sandbox",
    m.SecretSourceEnv("HTTP_CONNECT_PASSWORD"),
)
m.WithProxy(proxy)
```

```ruby Ruby
proxy = Microsandbox::OutboundProxy.http_connect("127.0.0.1:3128").credentials(
  "sandbox",
  Microsandbox::SecretSource.env("HTTP_CONNECT_PASSWORD")
)
```

```bash CLI
msb run alpine \
  --proxy http://127.0.0.1:3128 \
  --http-connect-username sandbox \
  --http-connect-password-env HTTP_CONNECT_PASSWORD
```
</CodeGroup>

- **Password source:** Set the password in a host environment variable, the only supported source. Configuration stores only the variable name, such as `HTTP_CONNECT_PASSWORD`, never the password.
- **When changes apply:** The password is read when the sandbox starts. Restart the sandbox after changing it.
- **Username:** RFC 7617 permits an empty username for token-only authentication. A non-empty username must not contain `:` or control characters.
- **Password:** The resolved password must not be empty.
- **407 responses:** A proxy that requires authentication is refused instead of retried without credentials. The error distinguishes missing credentials from rejected credentials.
- **Runtime support:** The selected `msb` runtime must advertise the HTTP CONNECT authentication capability. An older runtime fails the launch with an upgrade-required error instead of silently connecting unauthenticated.

<Warning>
  HTTP Basic authentication does not encrypt credentials in transit. Use a trusted local or private proxy, or encrypt the connection separately.
</Warning>

## Discover a proxy from the host environment

Enable opt-in ambient discovery when a corporate or developer environment already exports proxy variables. Only the enablement boolean is stored; the selected endpoint, its URL credentials, and the `NO_PROXY` rules stay in host memory and are reread at each runtime network startup.

```bash
msb run python --proxy-from-env
```

<CodeGroup>
```typescript TypeScript
await using sb = await Sandbox.builder("ambient")
  .image("python")
  .proxyFromEnv(true)
  .create();
```

```rust Rust
use microsandbox::Sandbox;

let sb = Sandbox::builder("ambient")
    .image("python")
    .proxy_from_env(true)
    .create()
    .await?;
```

```python Python
sb = await Sandbox.create("ambient", image="python", proxy_from_env=True)
```

```go Go
sb, err := m.CreateSandbox(ctx, "ambient",
    m.WithImage("python"),
    m.WithProxyFromEnv(true),
)
```

```ruby Ruby
sb = Microsandbox::Sandbox.create("ambient", image: "python", proxy_from_env: true)
```
</CodeGroup>

- **Default and overrides:** Off by default. `--proxy-from-env[=true|false]`, `network.proxy_from_env`, SDK setters, and `sandbox_defaults.proxy_from_env` set it. Explicit `false` is an override, not an omission, and an explicit outbound proxy wins over it.
- **Precedence:** An explicit `--proxy`/outbound proxy wins without reading any proxy variable. Multi-tenant deployments clear ambient intent before discovery, and cloud creation rejects it.
- **Policy:** Explicit values override ordinary user, global, and sandbox-file defaults. Managed configuration is applied last and is authoritative in both directions, so a managed `true` cannot be turned off by a per-sandbox or CLI `false`. See [corporate networking](/enterprise/corporate-networking) for managed enforcement.
- **Host toggle:** `MSB_PROXY_FROM_ENV=1|true|yes|on` (or `0|false|no|off`) supplies an ordinary default for new sandboxes. It is read when the SDK backend is constructed and never overrides an explicit per-sandbox value or managed policy.

<Accordion title="Variable precedence and endpoint selection">

- **Variables:** `https_proxy`, `http_proxy`, `all_proxy`, and `no_proxy`, plus their uppercase spellings. Lowercase wins; an empty lowercase value falls back to uppercase. Only `http://` endpoints (or a scheme-less `host:port`) are supported, with port 80 by default.
- **Preference:** TLS destinations try `HTTPS_PROXY`, then `ALL_PROXY`, then `HTTP_PROXY`. Other TCP destinations try `HTTP_PROXY`, then `ALL_PROXY`, then `HTTPS_PROXY`. No runtime failure falls back to another candidate.
- **TLS classification:** The preference is chosen when the guest opens the connection, before any TLS ClientHello exists, so a destination counts as TLS only on port 443 or a port configured for TLS interception. HTTPS on a nonstandard, unintercepted port uses the HTTP preference, which matters when the two variables point at different proxies.
- **Transport:** HTTP CONNECT only. `https_proxy` names a proxy for TLS destinations; it does not mean TLS to the proxy. Basic authentication comes from URL userinfo and is held only in host memory.

</Accordion>

<Accordion title="NO_PROXY rules and exclusions">

- **`NO_PROXY` syntax:** Comma or whitespace separated. Supports `*`, IP addresses, CIDR ranges, and domain names (exact or dot-delimited subdomains, case-insensitive, trailing dots ignored). Numeric ports on a rule are ignored.
- **Domain matching:** Domain rules match a live DNS answer for the destination IP, not SNI or PTR. If the guest never resolved a matching name, only IP/CIDR/`*` rules can exempt the destination.
- **Shared IPs:** Matching is per destination IP, so any live cached name that matches a rule exempts every hostname that currently resolves to the same address. Two hostnames behind one IP are therefore either both proxied or both direct. Use IP/CIDR rules when you need deterministic bypasses.
- **Local destinations:** Loopback, unspecified, and link-local host dial addresses, plus `host.microsandbox.internal`, stay direct.

</Accordion>

<Accordion title="Failures, limits, and restarts">

- **Missing settings:** When none of the proxy variables is set, routing stays direct and the runtime logs nothing.
- **Unusable settings:** A proxy variable that is present but unusable is ignored with a credential-free warning in the runtime log. If another usable proxy variable remains, traffic is proxied through it; traffic connects directly only when no usable proxy variable remains.
- **Failures after selection:** Once a proxy is selected, DNS, connect, handshake, timeout, or proxy-rejection failures fail that connection; there is no direct retry.
- **Limits:** Non-DNS UDP cannot travel over HTTP CONNECT and is dropped while ambient routing is selected. DNS, DNS-over-TLS, and ICMP keep their existing paths. Ambient discovery is not a mandatory egress tunnel; use an explicit proxy or network policy when traffic must never leave directly.
- **Restarts:** Each network-engine startup re-reads the launching host environment. Restarting reads the environment of the process performing the restart; changing the variables while a sandbox runs affects its next network start. Do not expect the saved configuration to remember the previously selected endpoint.
- **Runtime support:** The selected `msb` runtime must advertise the `proxy_from_env` capability. An older runtime fails with an upgrade-required error instead of routing direct.

</Accordion>

<Accordion title="Older SDKs and shared homes">

Only the enablement boolean is saved. Older SDKs/CLIs that can open the same home may silently remove saved `proxy_from_env=true` when rewriting sandbox settings; there is no new catalog marker or feature-specific downgrade guard. Runtime capability admission does not protect against that loss. Coordinate older SDK/CLI writers or use separate homes, and use supporting clients for managed enforcement.

</Accordion>

## Behavior and limits

- Network policy is evaluated against the sandbox's actual destination before the proxy connection is opened.
- HTTP CONNECT and SOCKS4 support TCP only. Non-DNS UDP is blocked while either is configured; SOCKS4 also cannot reach IPv6 destinations.
- SOCKS5 uses `CONNECT` for TCP and `UDP ASSOCIATE` for non-DNS UDP.
- DNS uses microsandbox's DNS forwarder instead of the configured proxy. This includes plain DNS, DNS-over-TCP, and DNS-over-TLS.
- Connections to `host.microsandbox.internal` bypass the proxy and continue to target the microsandbox host.
- Each TCP connection opens its own proxy connection and handshake. Each UDP flow opens its own SOCKS5 control connection and UDP association.
- HTTP CONNECT authentication uses HTTP Basic credentials on the CONNECT request; see [HTTP CONNECT credentials](#http-connect-credentials) for the 407 behavior.
- TLS interception and secret injection continue to work as configured.
