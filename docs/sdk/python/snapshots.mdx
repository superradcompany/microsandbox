Use snapshot objects or references on cloud. Local operations also accept a group head, `group:member`, or artifact path.

Export methods `save` and `save_to` accept the keyword `compatibility` (`"current"` by default, or `"0.7.8"`). ## Sandbox capture

<span id="sandbox-group-capture" />

#### <span className="msb-recv">sandbox.</span><span className="msb-hn">snapshot()</span>

```python
async def snapshot(
    self, name: str, *, initial_checkpoint: str | None = None,
    dest_dir: str | os.PathLike[str] | None = None,
    labels: dict[str, str] | None = None, full: bool = False,
    record_integrity: bool = False, guest_flush: str | None = None,
) -> SnapshotCreateResult
```

Available on `Sandbox` and `SandboxHandle`. `name` selects a new group; `initial_checkpoint` names its first member. `dest_dir` selects the parent storage directory. An existing group is refused. Omitted member names are generated; capture is disk-only by default. Set `full=True` to capture memory and device state, or `record_integrity=True` to record payload checksums. `guest_flush` accepts `"auto"`, `"required"` or `"skip"`; omission uses Auto.

<Accordion title="Example">

```python
from microsandbox import Sandbox, Snapshot

source = await Sandbox.get("worker")
created = await source.snapshot("history", initial_checkpoint="ready", record_integrity=True)
group = created.snapshot
next_capture = await group.checkpoint(name="after-build")
exact = await group.get_checkpoint("ready")
await group.set_head("ready")
await group.clear_head()
# Clearing selection keeps all checkpoints; use an exact member to spawn.
child = await exact.spawn_sandbox(name="child")
reopened = await Snapshot.get("history")
```

</Accordion>

Artifact helpers formerly owned by `Snapshot` are now accessed through `Checkpoint`. Existing `SnapshotHandle`, builder, archive, ID, and verification type names remain; this public object rename does not rewrite persisted artifact IDs. Retained artifact helpers below also cover supported cloud workflows, where local group operations return unsupported.

Clear selection while preserving every member. Clearing an already headless group reports a no-op.

<span id="group-checkpoint" />

#### <span className="msb-recv">group.</span><span className="msb-hn">checkpoint()</span>

```python
async def checkpoint(
    self, *, name: str | None = None, labels: dict[str, str] | None = None,
    full: bool = False, record_integrity: bool = False,
    guest_flush: str | None = None,
) -> CheckpointCaptureResult
```

Capture the bound sandbox and return the exact checkpoint and this operation’s head outcome. Imported or orphaned groups refuse capture; a same-name replacement sandbox never becomes the source. Omitted `name` is generated. `guest_flush` accepts `"auto"`, `"required"` or `"skip"`; omission uses Auto. An append does not accept a destination directory.

<span id="group-spawn" />

#### <span className="msb-recv">group.</span><span className="msb-hn">spawn_sandbox()</span>

```python
async def spawn_sandbox(self, *, name: str | None = None, **kwargs: Any) -> Sandbox
```

Select the group head once and retain it throughout destination preparation. A headless group refuses spawning. The same methods on an exact checkpoint retain that checkpoint instead. Full checkpoints resume execution by default; disk checkpoints boot fresh. Destination options cannot change the source selector or backend. The keywords are the destination controls documented under [Restore](#restore); unknown keywords are rejected.

<span id="group-spawn-progress" />

#### <span className="msb-recv">group.</span><span className="msb-hn">spawn_sandbox_with_progress()</span>

```python
async def spawn_sandbox_with_progress(
    self, *, name: str | None = None, **kwargs: Any
) -> PullSession
```

Local-only. Iterate the session for best-effort creation events, and await `session.result()` for authoritative completion. End of progress is not success. `session.cancel()` requests cancellation; consume the result to learn whether cancellation or completion won. The same destination keywords apply.

## Save an exact checkpoint

<Accordion title="Example">

```python
await checkpoint.save("ready.msb")
await checkpoint.save("portable.msb", with_parents=True, with_image=True)
```

</Accordion>

The receiver selects one immutable checkpoint. Use the group’s optional head or exact-member lookup first; saving a group’s whole history is not implied. The no-options call writes a compressed `.msb` archive. `save_to` retains its explicit options form for compatibility. See the archive compatibility option below before sending output to an older reader.

## Group archive import

<span id="group-load" />

#### <span className="msb-recv">Snapshot.</span><span className="msb-hn">load()</span>

```python
async def load(
    group: str, files: list[str | os.PathLike[str]], *,
    dest: str | os.PathLike[str] | None = None, base: str | None = None,
    set_head: bool = False,
) -> SnapshotImportResult
```

Import a batch atomically. `dest` selects the parent storage directory; omission uses default storage. `base` supplies an external dependency snapshot or archive. `set_head=True` selects the unique imported tip even when it is not a fast-forward; ambiguous tips are refused.

<Accordion title="Example">

```python
await Snapshot.load(group, files, dest="store", base="base.msb", set_head=True)
```

</Accordion>

`files` is a list of host paths. The keyword options are optional. Returns `SnapshotImportResult` with `snapshot`, `checkpoints`, `added`, `reused`, `head_update`, `operation_id`, and `warnings` properties.

The result contains every unique supplied checkpoint, including bundled dependencies, in stable ID order. `added` and `reused` identify what was new versus already installed at publication; archive argument order does not select the head. The head outcome belongs to this operation and does not change when another operation edits the group. Multiple incomparable tips can commit a headless group; explicit head selection refuses ambiguous tips.

A successful return confirms publication and catalog completion. Warnings describe deferred cleanup after commit. A structured import error distinguishes no publication, confirmed publication with a later failure, and an unknown outcome needing recovery. Import never binds a group to a source sandbox. See [atomic import requirements](/cli/snapshot-commands#msb-snap-import) for filesystem capabilities and maintenance requirements.

## Group inspection

<span id="group-inspect" />

#### <span className="msb-recv">group.</span><span className="msb-hn">inspect()</span>

```python
async def inspect(self) -> SnapshotGroupInfo
```

Returns the group's name, backend path, optional head, member count and optional saved source binding. Head and count come from one protected metadata read. Field names include `checkpoint_count`, `source.recorded_name`, `source.current_name`, `source.database_uuid`, `source.sandbox_id`; access them as dictionary keys, for example `info["source"]["recorded_name"]`. The source is absent for an unbound history; otherwise its status is `available`, `missing_sandbox` or `different_catalog`. Saved and current names distinguish renames; identity is the catalog UUID plus sandbox row ID, so deleting and recreating the same name does not rebind the group.

Source availability is observed separately from group metadata and is not a guarantee of later capture readiness. Inspection does not change the selected head or create a missing catalog identity. Invalid metadata and database failures remain errors, rather than being reported as unbound. Obtain a member with `get_checkpoint` for its immutable metadata.

## Group verification

<span id="group-verify" />

#### <span className="msb-recv">group.</span><span className="msb-hn">verify()</span>

```python
async def verify(self) -> dict[str, Any]
```

`await (await Snapshot.get("worker")).verify()` checks all pinned members and returns a dictionary with `group`, `state`, `checkpoints`, and `payload_hashes`. States distinguish `complete`, `incomplete`, `invalid`, and `empty` (zero checkpoints checked). Every member includes `id`, `path`, `state`, optional `report` using the existing checkpoint verification fields, and specific `findings`. Headless groups can be verified; to check only head, obtain the optional checkpoint and call its `verify()`.

Unrecorded checksums remain incomplete. Corruption, missing files, unsupported requirements, and operational failures raise `SnapshotVerificationError` with the full dictionary in `error.report`; failures before a meaningful report exists retain their ordinary exception. Shared physical payloads are hashed once per algorithm, independent copies are checked separately, and cancellation retains reader protection until hashing finishes.

Selected members remain protected through hashing, including cancellation. Same-group captures, imports and head changes wait until verification finishes. Concurrent older removers must be stopped or upgraded; reads and sandbox execution can continue.

## Whole-group removal

<span id="group-remove" />

#### <span className="msb-recv">group.</span><span className="msb-hn">remove()</span>

```python
async def remove(self) -> SnapshotRemoveResult
```

Removes the selected history and returns `SnapshotRemoveResult` with `group`, `removed`, `head_update`, and `warnings`. The member IDs and cleared-head outcome belong to this operation. Empty groups can be removed. Active readers and surviving external dependents refuse removal; there is no force bypass for an entire group.

If publication commits but catalog cleanup fails, the call raises `SnapshotGroupRemovalRecoveryError` with `result` and `detail`. The attached result means removal already happened. Cleanup warnings after successful catalog reconciliation are returned in the result. An uncertain durability outcome is an error requiring recovery rather than a claimed successful removal. Later listing recovers pending cleanup without deleting a replacement group.

## Exact checkpoint removal

Migration: static Python `Snapshot.remove(reference, force=...)` becomes `Checkpoint.remove_by_reference(reference, force=...)`. The canonical `Checkpoint.remove()` is now an instance method. Legacy `SnapshotHandle.remove(force=...)` still returns `None`.

<Accordion title="Example">

```python
removed = await checkpoint.remove()
forced = await checkpoint.remove(force=True)
```

</Accordion>

These are alternative calls, not successive removals of the same checkpoint. The instance method removes the retained checkpoint identity, refuses a replacement at the same address, and returns `CheckpointRemoveResult` with `id`, optional `head_update`, and `warnings` properties. The head outcome belongs to this operation; later head edits do not change it. Removing the head selects its surviving same-group parent or clears selection. Removing another member reports an unchanged head. Standalone artifacts have no head outcome.

Force permits removal despite indexed children, but never bypasses reader protection. A repeated removal reports a missing checkpoint rather than fabricating another successful result. Backends or native libraries without exact-removal reporting return unsupported instead of falling back to deletion by name.

If removal commits but catalog cleanup fails, the call raises `SnapshotRemovalRecoveryError`, with `result` and `detail`. Its result is authoritative: removal already happened. Recover the affected storage before retrying cleanup; do not assume an error means the checkpoint still exists.

## Capture recovery

A failed capture can still have published its requested artifact before source recovery failed. `SnapshotSourceRecoveryError` preserves the source checkpoint recovery locator and, when publication completed, the published artifact’s kind, path, identity, digest and `head_update`. The head outcome belongs to that publication even if another operation changes the group afterward. Archive-only capture and older producers omit it; do not infer it by reading the current head. Inspect those details before retrying or removing the source. The error does not prove that the source is running or safely paused.

## Guest writeback

Pass `guest_flush=GuestFlush.REQUIRED` to `Checkpoint.create`, `Checkpoint.create_archive`, `source.fork`, `source.fork_many`, or `source.pause`. Import `GuestFlush` from `microsandbox`.

The default `AUTO` flushes live disk-only captures, but adds no optional flush to full captures, forks, or pause. `SKIP` retains mandatory storage barriers.

A paused disk capture needs a matching prior flush; cloud rejects non-Auto policies. See [guest flush policy reference](/sandboxes/snapshots#guest-flushing).

## Forking

Fork a running or paused local sandbox to create a child with copy-on-write memory. The source returns to its previous state, and each child needs an unused name. `SandboxHandle` has the same methods. See the [forking guide](/sandboxes/snapshots#forking) for backend limits and disk bindings.

### fork()

```python

```

<Accordion title="Example">

```python
child = await sb.fork("experiment")
try:
    result = await child.exec("python", ["-V"])
    print(result.stdout_text)
finally:
    await child.stop()
```

</Accordion>

Create one child from the current execution state.

### fork_many()

```python
async def fork_many(self, names: list[str], *, record_integrity: bool = False,
                    guest_flush: GuestFlush | None = None,
                    volumes: Mapping[str, MountConfig] | None = None) -> list[ForkOutcome]: ...
```

<Accordion title="Example">

```python
outcomes = await sb.fork_many(["alice", "bob"])
for outcome in outcomes:
    if outcome.sandbox is not None:
        await outcome.sandbox.stop()
    else:
        print(outcome.name, outcome.error)
```

</Accordion>

Capture once for all names and return outcomes in input order. Each outcome has `name`, plus a started `sandbox` or an `error`; the other field is `None`. Validation or capture errors raise for the whole call; a child startup error leaves successful siblings running. Stop successful children when finished.

`record_integrity` records disk hashes. `guest_flush` defaults to `GuestFlush.AUTO`; see [guest writeback](#guest-writeback) for policy details. `volumes` rebinds captured disks; forks cannot add new block devices, and batch children cannot share a writable disk image. See [fork disk bindings](/sandboxes/snapshots#forking). `branch()` and `branch_many()` remain deprecated aliases that emit `DeprecationWarning`; `BranchOutcome` aliases `ForkOutcome`.

#### init

```python
init: str | InitConfig | Mapping[str, Any] | None = None
```

Select guest PID 1 for disk boot using an absolute guest executable path, `"auto"`, or the existing `InitConfig(cmd, args, env)` form. Available on group/checkpoint `spawn_sandbox`, progress variants, and `Sandbox.restore`. Full-memory resume rejects an explicit choice, including `"auto"`; select `disk_only=True` for a new boot.

#### max_cpus and max_memory

```python
max_cpus: int | None = None
max_memory: int | None = None
```

Set the maximum possible CPU count and memory ceiling in MiB for a disk boot, including `disk_only=True`. Values must be positive and at least the requested capacity; full-memory resume requires the captured ceilings exactly. `None` leaves a ceiling unspecified. Available on group/checkpoint spawn and progress variants as well as restore.

#### Destination command defaults

Use `workdir`, `shell`, `entrypoint`, `cmd` and `env` keyword arguments to configure new commands in the destination. They work for disk boots and full resumes without changing captured processes or starting a workload during restoration. An explicit empty entrypoint or CMD clears that default; omission keeps existing resolution. Environment defaults combine with per-command overrides through the ordinary SDK rules. Guest working directories must exist. These are explicit destination settings, not automatically saved snapshot configuration. Unsupported native bindings reject new explicit options before dispatch.

#### labels

```python
labels: Mapping[str, str] | None = None
```

Attach destination sandbox labels. Source snapshot labels remain unchanged. Available on group/checkpoint spawn, progress variants and restore; normal sandbox label validation applies.

#### pull_policy

```python
pull_policy: PullPolicy | None = None
```

Control retrieval of the snapshot's recorded image digest. The default `if-missing` and explicit `never` can use complete local/archive content offline. `always` revalidates that exact digest through its registry, even when cached, and fails if the registry cannot provide it. This never follows the original mutable tag or changes the source snapshot. Explicit use requires an updated native binding and is refused before dispatch when unsupported.

#### proxy

```python
proxy: OutboundProxy | None = None
```

Select the destination host proxy before disk boot or full-memory resume. This preserves the captured guest interface and does not inject guest trust material. SOCKS5 passwords use destination environment references; resolved passwords are not saved in snapshot configuration. `None` leaves destination resolution unchanged.

#### hostname

```python
hostname: str | None = None
```

Set a nonempty guest hostname of at most 64 UTF-8 bytes for disk boot. Full-memory resume refuses replacement even when the requested name matches the source. `None` leaves the choice unspecified.

Image, replacement, and automatic startup-command options are not accepted; entrypoint/CMD configure future commands only. Full restore requires matching CPU and memory settings, keeps captured network devices, and cannot apply a new guest security profile. Use disk-only restore to change these.

Restore rejects missing external filesystems (and, for full restore, additional disks) by default. Use `allow_missing_resources=True` to resume with unavailable devices (full restore records warnings). This is separate from strict/relaxed validation of supplied mappings; inheritance does not waive missing backing. Root and owned storage remain required.

Omitted controls retain destination defaults. Durations are non-negative finite seconds, rounded up. Network policy accepts `NetworkPolicy`, not `Network`. `captured_volumes` contains guest paths.

Full capture records the source clock policy; current disk capture does not. An explicit sync policy overrides a saved off policy. The same option is available on group and checkpoint spawn, including progress variants. Clock selection controls guest wall-clock synchronization. Unsupported native SDKs or runtimes refuse unsupported explicit selection before launching the destination.

## Compaction

Compact a local sandbox’s root or owned disks. See [compaction](/sandboxes/snapshots#compact-disks) for examples and recovery requirements.


<div className="msb-params">
  <div className="msb-param">
    <div className="msb-param-key"><code>disk</code></div>
    <div className="msb-param-desc">Select one owned disk by guest path; <code>/</code> selects the root.</div>
  </div>
  <div className="msb-param">
    <div className="msb-param-key"><code>root_disk_only</code></div>
    <div className="msb-param-desc">Select only the root. Cannot combine with the disk selector.</div>
  </div>
  <div className="msb-param">
    <div className="msb-param-key"><code>layers</code></div>
    <div className="msb-param-desc">Oldest sealed layers to merge, including the base. Minimum two; omit for all. Excludes the writable layer.</div>
  </div>
  <div className="msb-param">
    <div className="msb-param-key"><code>dry_run</code></div>
    <div className="msb-param-desc">Preview without changing storage.</div>
  </div>
</div>

Defaults to the root and owned data disks; excludes named/external volumes and directories. Requires a running or fully stopped local sandbox. Fewer than two sealed layers means no change; no eligible disks returns an empty result with zero counts.

Results include aggregate counts and per-disk entries keyed by `guest_path`. `materialized_bytes` counts copied bytes, not reclaimed space. Times are microseconds: per-disk `total_us` covers preparation; aggregate `total_us` also includes switching; `pause_us` measures the shared VM pause.
