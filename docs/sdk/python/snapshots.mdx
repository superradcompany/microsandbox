Create local disk snapshots of running, paused, stopped, or crashed sandboxes, or full checkpoints of running and paused sandboxes. Cloud disk snapshots use managed storage or the organization's host volume. See [Snapshots](/sandboxes/snapshots) for usage and lifecycle concepts.

<Note>
Cloud supports disk snapshot create, get, list, open, remove, and dedicated restore for stopped or crashed sources. Live capture, full checkpoints, branching, groups, archive import/export/copy, verification, and disk maintenance remain local-only. Unsupported options return an explicit error before mutation. Pass snapshot objects or typed references instead of assuming that cloud storage is a path on the client host.
</Note>

## Snapshot groups

Installed snapshots belong to a group. A bare group selects its head; `group:member` selects a member by name or stable snapshot ID. Artifact paths remain valid selectors. Creation defaults to the source sandbox's group and generates a member name when omitted; imports without `group=` create a new generated group. `dest_dir` and `dest` select the parent directory containing groups.

```python
snap = await Snapshot.create("baseline", from_sandbox="box", group="work")
loaded = await Snapshot.load("changes.msb", base="work:baseline", group="work")
head = await Snapshot.group_head("work")
selected = await Snapshot.group_head("work:baseline")
# Explicitly select an imported member even when it is not a descendant.
loaded = await Snapshot.load("other.msb", group="work", set_head=True)
```

`group_head(selector)` returns a dictionary with `group`, `previous`, `head`, `reason`, and `changed`. `previous` and `head` are stable snapshot IDs. Automatic head updates initialize an empty group or advance to a proven descendant; divergent imports and imports with unknown ancestry retain the current head. Reasons are `initialized`, `fast_forwarded`, `selected`, `unchanged`, `diverged`, `unknown_ancestry`, and `ambiguous_candidates`. Direct archive capture creates no group and rejects `group=`.

## Load multiple archives

```python
from pathlib import Path

handles = await Snapshot.load_many(
    list(Path("checkpoints").glob("*.msb")),
    group="received",
)
```

`load_many(archives, *, dest=None, base=None, group=None, set_head=False)` returns one `SnapshotHandle` for each supplied archive, in input order. The batch resolves dependencies regardless of argument order, using its archives and exact matching members already installed in an explicitly named destination group. `base` provides an external snapshot or standalone archive when needed. Single-file `load` also reuses dependencies from its named destination group. Omitting `group` creates one generated group for the whole batch.

The importer validates the complete batch before publishing members. `set_head=True` requires a unique tip. With divergent tips and the default `False`, an existing head is retained (`ambiguous_candidates`); a new group has no head and imported handles report `head_update=None`. Select a member explicitly to give that group a head. Existing archive formats are unchanged. The CLI equivalent is `msb snapshot load checkpoints/*.msb --group received`, with `--dest DIR` for another group-store root.

`Snapshot.path` and `SnapshotHandle.path` remain available for local snapshots.
These accessors are deprecated and raise `UnsupportedError` if no local filesystem
path exists. Use `reference` for backend-neutral code.

## Restore a sandbox

```python
child = await Sandbox.restore("api:baseline", name="api-restored", forked=True)
```

`Sandbox.restore(snapshot, *, name, ...)` accepts a group head, `group:member`, artifact directory, or archive. The returned sandbox is detached. Disk snapshots cold-boot; full snapshots resume captured execution without a new startup command.

Use `forked=True` for private CoW RAM, `disk_only=True` for only a full snapshot's disk, and `snapshot_base="group:member"` for a dependent archive. `Sandbox.restore_with_progress()` accepts the same options and returns a `PullSession`. Image, replacement, and startup-command options are rejected.

Destination options include `cpus`, `memory` (MiB), `network_policy`, `max_connections`, `disable_network`, `security`, `max_duration`, and `idle_timeout`. `network_policy` accepts the existing `NetworkPolicy` type, not a `Network` configuration; it changes host-side filtering without implicitly configuring DNS, TLS, or bootstrap. Durations are non-negative finite seconds rounded up to whole seconds; explicit zero requests immediate expiry. Omit lifetime options or leave them `None` for no limit by default. In contrast, `max_connections=0` means no connection cap. Other omitted controls retain destination defaults.

Full execution restore requires CPU and memory overrides to match captured geometry exactly, and rejects removing a captured NIC. Host-side network policy, connection limits, and lifetime limits can change. An explicit `SecurityProfile`—including `SecurityProfile.DEFAULT`—requires a disk snapshot or `disk_only=True`; it cannot change already-captured execution.

Supply destination bindings with `volumes`, `ports`, and `vsock`, using the same typed values as creation. `captured_volumes=["/data"]` selects private captured disks. `user` changes the default for new execs, and `log_level` configures host logging. Resources are not inherited unless `dangerously_inherit_resources=True` is explicit. `external_mount_policy="strict"` (default) or `"relaxed"` validates supplied filesystem mappings, not permission to inherit them.

## Disk maintenance and incremental export

Exporting since a base omits reusable root/owned-disk layers and RAM objects. Every disk shared with the base must retain its exact physical prefix; compaction of any such disk requires a new standalone baseline. New owned disks are included completely. Owned directory namespaces stay complete while unchanged file payloads can come from the base. Full checkpoints keep the complete memory map and CPU/device state. The last-layers option selects only the newest root-disk layers, retaining complete owned disks and RAM payloads. Imports resolve dependencies from the batch or an explicitly named destination group. Use an external base for missing dependencies; direct restore still accepts an explicit base. Selective export cannot be combined with whole-group/with-parents export.

```python
worker = await Sandbox.get("worker")
plan = await worker.compact(layers=3, dry_run=True)
result = await worker.compact(layers=3)
await Snapshot.save("worker:checkpoint-b", "changes.msb", since="worker:checkpoint-a")
await Snapshot.load("changes.msb", base="worker:checkpoint-a")
child = await Sandbox.restore("changes.msb", name="child", snapshot_base="worker:checkpoint-a")
```

Compaction defaults to the managed or flat root and all sandbox-owned data disks, never named/external disks or directories. Pass `disk="/data"` to select one owned disk, or `root_disk_only=True` for only the root; these selectors are mutually exclusive. `disk="/"` also selects the root. `layers` limits each disk to up to N oldest sealed physical layers including the base, excluding the writable head; N must be at least two. Omit it to compact all sealed layers. Chains with fewer than two sealed layers are unchanged. Results are dictionaries with aggregate `input_layers`, `selected_layers`, `output_layers`, `materialized_bytes`, `total_us`, `pause_us`, and `dry_run`, plus per-disk `disks` entries keyed by `guest_path`. With no eligible disks the default succeeds with an empty list and zero layer and byte counts. Compaction requires a running or fully stopped local sandbox; multi-disk commits can require [journal-based recovery](/sandboxes/snapshots#export-changes-and-compact-a-disk-chain).

Per-disk `total_us` measures preparation/materialization only; aggregate `total_us` also includes journal adoption and backend switching, and `pause_us` measures the shared VM pause. Timings are microseconds.

Use `last_layers=n` instead of `since` to export the newest N sealed root-disk layers. Owned disks are included completely. See [disk-chain maintenance](/sandboxes/snapshots#export-changes-and-compact-a-disk-chain) for dependency and retention rules.

| `labels` | `dict[str, str]` | User-supplied labels |
