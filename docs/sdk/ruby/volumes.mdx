## Volume instance

Creation, lookup and list items return the same `Microsandbox::Volume` class. Dropping the object does not delete storage.

#### <span className="msb-recv">volume.</span><span className="msb-hn">id</span>

```ruby
volume.id # => String
```

An opaque identity for this connection. Reading it does not contact the backend; a replacement with the same name has a different identity.

#### <span className="msb-recv">volume.</span><span className="msb-hn">path</span>

```ruby
volume.path # => String
```

Host path for local storage. Remote volumes report an unsupported-operation error.

#### <span className="msb-recv">volume.</span><span className="msb-hn">info</span>

```ruby
info = volume.info
puts info.fetch("quota_mib")
puts info.fetch("used_bytes")
puts info.fetch("labels")
```

Fetch the current quota, usage, capacity, labels, and metadata from the backend. The method performs a fresh lookup on each call; unknown usage is `nil` and lookup errors do not return captured data. Reuse this returned hash when several values should come from the same lookup.

## Volume.local / Volume.remote

```ruby
Microsandbox::Volume.local  # => Volumes
Microsandbox::Volume.remote # => Volumes
```

Select before creation/lookup/listing; the collection retains its destination. Remote selection captures environment credentials and raises on invalid configuration. Neither selector changes an existing resource or global default. See [selector examples](/operations/backends#resource-selectors).
