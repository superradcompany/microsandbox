## LocalContext

#### new

```ruby
Microsandbox::LocalContext.new(home: nil, config_path: nil) # => LocalContext
```

Capture a local destination. Construction does not start a VM. Collections and resources retain these settings.

## RemoteContext

#### new

```ruby
Microsandbox::RemoteContext.new(url: nil, api_key: nil, profile: nil, request_timeout_ms: nil, user_agent: nil, compute_type: nil) # => RemoteContext
```

Capture a remote API destination using explicit credentials or a named profile. `request_timeout_ms` must be a nonnegative integer. `compute_type` accepts `"standard"` or `"shared"` for new sandboxes; omission uses the server default. See [compute types](/cloud/pricing#choose-a-compute-type).

#### with_url

```ruby
Microsandbox::RemoteContext.with_url(url, api_key, request_timeout_ms: nil, user_agent: nil, compute_type: nil) # => RemoteContext
```

Select an explicit compatible remote endpoint. An empty URL is invalid. Key-only `new(api_key: ...)` uses `MSB_API_URL` or the hosted endpoint.

#### with

```ruby
remote.with(url: nil, api_key: nil, request_timeout_ms: nil, user_agent: nil, compute_type: nil) # => RemoteContext
```

Return an independent context using keyword overrides. Nil retains the captured value. Profiles, environment and configuration files are not read again; existing resources keep their destination. Empty URLs/keys and invalid timeouts fail. See [derivation examples](/cloud/connect#deriving-a-remote-context).

#### from_env / from_profile

```ruby
Microsandbox::RemoteContext.from_env # => RemoteContext
Microsandbox::RemoteContext.from_profile(name) # => RemoteContext
```

`from_env` reads `MSB_API_KEY` and optional `MSB_API_URL`. Existing contexts and resources keep their destination.
