## Sandbox capture

#### <span className="msb-recv">sandbox.</span><span className="msb-hn">snapshot()</span>

```rust
async fn snapshot(&self, group: &str) -> MicrosandboxResult<SnapshotCreateResult>
```

Create a source-bound group and its first disk checkpoint with default capture options. Available on both `Sandbox` and `SandboxHandle`; an existing group is refused.

<span id="group-lifecycle-and-08-migration" />

#### <span className="msb-recv">sandbox.</span><span className="msb-hn">snapshot_with()</span>

```rust
async fn snapshot_with(
    &self,
    group: &str,
    configure: impl FnOnce(SnapshotCaptureOptions) -> SnapshotCaptureOptions,
) -> MicrosandboxResult<SnapshotCreateResult>
```

Create a new group through a sandbox or sandbox handle, then capture later checkpoints through that group. The initial call refuses an existing group; an append uses its saved source identity. Imported or orphaned groups cannot capture, and recreating a sandbox with the same name does not rebind them.

<Accordion title="Example">

```rust
use microsandbox::{Sandbox, Snapshot};

let source = Sandbox::get("worker").await?;
let created = source.snapshot_with("history", |capture| {
    capture.initial_checkpoint("ready").record_integrity()
}).await?;
let group = created.snapshot;
let next = group.checkpoint_with(|capture| capture.name("after-build")).await?;
let exact = group.get_checkpoint("ready").await?;
group.set_head("ready").await?;
group.clear_head().await?;
// Clearing selection keeps all checkpoints; use an exact member to spawn.
let child = exact.spawn_sandbox_with(|destination| destination.name("child")).await?;
let reopened = Snapshot::get("history").await?;
```

</Accordion>

Returns `SnapshotCreateResult` with the group, exact first checkpoint and publication-owned head outcome. Read that checkpoint when you need the artifact produced by this call; another capture may already have moved head. An omitted member name is generated. Full capture and integrity recording are explicit options.

```rust
async fn checkpoint(&self) -> MicrosandboxResult<CheckpointCaptureResult>
```

Capture the bound source using a generated member name and default disk-only capture policy.

#### <span className="msb-recv">group.</span><span className="msb-hn">checkpoint_with()</span>

```rust
async fn checkpoint_with(
    &self,
    configure: impl FnOnce(SnapshotCaptureOptions) -> SnapshotCaptureOptions,
) -> MicrosandboxResult<CheckpointCaptureResult>
```

Capture the bound source with `SnapshotCaptureOptions`; return `CheckpointCaptureResult` with the exact checkpoint and its publication-owned head outcome. Imported or orphaned groups refuse capture; a same-name replacement sandbox does not rebind them. One sandbox may have several groups, but each group binds one sandbox instance. An existing group’s destination cannot be changed by capture options.

#### <span className="msb-recv">Snapshot::</span><span className="msb-hn">load()</span>

```rust
async fn load(
    group: impl AsRef<str>,
    files: &[PathBuf],
) -> MicrosandboxResult<SnapshotImportResult>
```

Import an archive set into a named history using default options. See `load_with()` for publication and result semantics.

<span id="group-archive-import" />

#### <span className="msb-recv">Snapshot::</span><span className="msb-hn">load_with()</span>

```rust
async fn load_with(
    group: impl AsRef<str>,
    files: &[PathBuf],
    configure: impl FnOnce(SnapshotImportOptions) -> SnapshotImportOptions,
) -> MicrosandboxResult<SnapshotImportResult>
```

<Accordion title="Example">

```rust
use microsandbox::Snapshot;

Snapshot::load(group, files).await?;
Snapshot::load_with(group, files, |load| load.dest_dir("store").base("base.msb").set_head()).await?;
```

</Accordion>

`group` is a name and `files` is `&[PathBuf]`. The callback receives `SnapshotImportOptions`, with destination/base/head controls and no second group selector. Legacy artifact-loading methods retain `LoadOpts` and its optional `group` field. Returns `SnapshotImportResult`: `snapshot`, `checkpoints`, `added`, `reused`, `head_update`, `operation_id`, and `warnings`.

The result contains every unique supplied checkpoint, including bundled dependencies, in stable ID order. `added` and `reused` identify what was new versus already installed at publication; archive argument order does not select the head. The head outcome belongs to this operation and does not change when another operation edits the group. Multiple incomparable tips can commit a headless group; explicit head selection refuses ambiguous tips.

A successful return confirms publication and catalog completion. Warnings describe deferred cleanup after commit. A structured import error distinguishes no publication, confirmed publication with a later failure, and an unknown outcome needing recovery. Import never binds a group to a source sandbox. See [atomic import requirements](/cli/snapshot-commands#msb-snap-import) for filesystem capabilities and maintenance requirements.

<span id="group-inspection" />

#### <span className="msb-recv">group.</span><span className="msb-hn">inspect()</span>

```rust
async fn inspect(&self) -> MicrosandboxResult<SnapshotGroupInfo>
```

Returns the group's name, backend path, optional head, member count and optional saved source binding. Head and count come from one protected metadata read. Field names include `checkpoint_count`, `source.recorded_name`, `source.current_name`, `source.database_uuid`, `source.sandbox_id`. The source is absent for an unbound history; otherwise its `SnapshotSourceStatus` is `Available`, `MissingSandbox` or `DifferentCatalog`. Saved and current names distinguish renames; identity is the catalog UUID plus sandbox row ID, so deleting and recreating the same name does not rebind the group.

Source availability is observed separately from group metadata and is not a guarantee of later capture readiness. Inspection does not change the selected head or create a missing catalog identity. Invalid metadata and database failures remain errors, rather than being reported as unbound. Obtain a member with `get_checkpoint` for its immutable metadata.

<span id="group-verification" />

#### <span className="msb-recv">group.</span><span className="msb-hn">verify()</span>

```rust
async fn verify(&self) -> MicrosandboxResult<SnapshotGroupVerifyReport>
```

Checks every pinned member and returns `SnapshotGroupVerifyReport`. Its `state` distinguishes `Complete`, `Incomplete`, `Invalid`, and `Empty`; `checkpoints` preserves each member's identity, path, optional existing `SnapshotVerifyReport`, and findings. `payload_hashes` counts physical payload hash passes, deduplicated per algorithm. Headless groups are valid, while empty groups report zero checked. To check only head, obtain `group.head()` and verify that checkpoint.

Missing checksums return explicit incomplete coverage. Corruption, missing files, unsupported required features, and operational failures return `MicrosandboxError::SnapshotVerification(report)` when a meaningful group report exists; failures before selection return the ordinary SDK error. Inspect the attached report without treating the failed call as success. Selected payloads stay reader-pinned until verification finishes, including after caller cancellation. Same-group captures, imports and head changes wait for hashing to finish. Concurrent older removers must be stopped or upgraded; reads and sandbox execution can continue.

<span id="whole-group-removal" />

#### <span className="msb-recv">group.</span><span className="msb-hn">remove()</span>

```rust
async fn remove(&self) -> MicrosandboxResult<SnapshotRemoveResult>
```

Removes the selected history and returns `SnapshotRemoveResult` with `group`, `removed`, `head_update`, and `warnings`. The member IDs and cleared-head outcome belong to this operation. Empty groups can be removed. Active readers and surviving external dependents refuse removal; there is no force bypass for an entire group.

If publication commits but catalog cleanup fails, the call raises or returns `MicrosandboxError::SnapshotGroupRemovalRecovery { result, source }`. The attached result means removal already happened. Cleanup warnings after successful catalog reconciliation are returned in the result. An uncertain durability outcome is an error requiring recovery rather than a claimed successful removal. Later listing recovers pending cleanup without deleting a replacement group.

#### <span className="msb-recv">group.</span><span className="msb-hn">spawn_sandbox()</span>

```rust
async fn spawn_sandbox(&self) -> MicrosandboxResult<Sandbox>
```

Group spawn selects head once and retains that member while preparing the destination. An unselected head fails. Full checkpoints resume execution by default; disk checkpoints boot fresh. Destination callbacks use `RestoreBuilder` and cannot replace the selected source. See [destination options](#restorebuilder).

Configure destination options for the selected head.

## SnapshotSourceRecoveryError

<span id="capture-recovery" />

A failed capture can still have published its requested artifact before source recovery failed. `SnapshotSourceRecoveryError` preserves the source checkpoint recovery locator and, when publication completed, the published artifact’s kind, path, identity, digest and `head_update`. The head outcome belongs to that publication even if another operation changes the group afterward. Archive-only capture and older producers omit it; do not infer it by reading the current head. Inspect those details before retrying or removing the source. The error does not prove that the source is running or safely paused.

#### <span className="msb-recv">Checkpoint::</span><span className="msb-hn">save_by_reference()</span>

#### <span className="msb-recv">checkpoint.</span><span className="msb-hn">remove()</span>

```rust
async fn remove(&self) -> MicrosandboxResult<CheckpointRemoveResult>
```

Migration: static Rust `Snapshot::remove(reference, force)` becomes `Checkpoint::remove_by_reference(reference, force)`. Use the instance method below for exact identity and a removal result. Legacy `SnapshotHandle::remove(force)` retains its unit-returning contract.

<Accordion title="Example">

```rust
let removed = checkpoint.remove().await?;
let forced = checkpoint.remove_with(|options| options.force()).await?;
```

</Accordion>

These are alternative calls, not successive removals of the same checkpoint. The instance method removes the retained checkpoint identity, refuses a replacement at the same address, and returns `CheckpointRemoveResult` with `id`, optional `head_update`, and `warnings`. The head outcome belongs to this operation; later head edits do not change it. Removing the head selects its surviving same-group parent or clears selection. Removing another member reports an unchanged head. Standalone artifacts have no head outcome.

Force permits removal despite indexed children, but never bypasses reader protection. A repeated removal reports a missing checkpoint rather than fabricating another successful result. Backends or native libraries without exact-removal reporting return unsupported instead of falling back to deletion by name.

If removal commits but catalog cleanup fails, the call returns `MicrosandboxError::SnapshotRemovalRecovery { result, source }`. Its result is authoritative: removal already happened. Recover the affected storage before retrying cleanup; do not assume an error means the checkpoint still exists.

## Forking

Fork a running or paused local sandbox to create a child with copy-on-write memory. The source returns to its previous state, and each child needs an unused name. `SandboxHandle` has the same methods. See the [forking guide](/sandboxes/snapshots#forking) for backend limits and disk bindings.

### fork()

```rust
fn fork(&self, name: impl Into<String>) -> ForkBuilder
```

<Accordion title="Example">

```rust
let child = source.fork("experiment").fork().await?;
let out = child.exec("python", ["-V"]).await?;
println!("{}", out.stdout()?);
child.stop().await?;
```

</Accordion>

Build one child from the current execution state; call `.fork().await` to start it.

### fork_many()

```rust
fn fork_many(&self, names: impl IntoIterator<Item = impl Into<String>>) -> ForkManyBuilder
```

<Accordion title="Example">

```rust
let outcomes = source.fork_many(["alice", "bob"]).fork().await?;
for outcome in outcomes {
    match outcome.result {
        Ok(child) => child.stop().await?,
        Err(error) => eprintln!("{}: {error}", outcome.name),
    }
}
```

</Accordion>

Capture once for all names and return outcomes in input order. Each `ForkOutcome` has a `name` and a `result` for that child. Validation or capture errors fail the outer call; a child startup error leaves successful siblings running. Stop successful children when finished.

The builders support `.record_integrity()`, `.guest_flush(GuestFlush::Required)`, and `.volume()` for rebinding captured disks. Forks cannot add new block devices, and batch children cannot share a writable disk image. See [fork disk bindings](/sandboxes/snapshots#forking).

The single-child builder also exposes `.fork_with_progress()` with the `local` feature. Import `GuestFlush` from `microsandbox::snapshot`; see [guest writeback](#guest-writeback) for the policy.

`ForkOutcome.name` is a `String`; `ForkOutcome.result` is a `MicrosandboxResult<Sandbox>`.

`branch()`, `branch_many()`, the builder `.branch()` terminal, `.branch_with_progress()`, and the `BranchBuilder`, `BranchManyBuilder`, and `BranchOutcome` types remain deprecated aliases.
