Create local disk snapshots of running, paused, stopped, or crashed sandboxes, or full checkpoints of running and paused sandboxes. Cloud disk snapshots use managed storage or the organization's host volume. See [Snapshots](/sandboxes/snapshots) for usage and lifecycle concepts.

<Note>
Cloud supports disk snapshot create, get, list, open, remove, and dedicated restore for stopped or crashed sources. Live capture, full checkpoints, branching, groups, archive import/export/copy, verification, and disk maintenance remain local-only. Unsupported options return an explicit error before mutation. Pass snapshot objects or typed references instead of assuming that cloud storage is a path on the client host.
</Note>

## Restore a sandbox

```go
child, err := m.RestoreSandbox(ctx, "api:baseline", "api-restored", m.WithForked())
```

`RestoreSandbox` accepts an installed selector or archive and returns a detached sandbox. Disk snapshots cold-boot; full snapshots resume captured execution. Use `WithForked()` for CoW RAM, `WithSnapshotDiskOnly()` for disk-only restore, and `WithSnapshotBase(base)` for dependent archives. `RestoreSandboxWithProgress` provides progress events and a result channel.

Use `WithRestoreConfig(RestoreConfig{...})` for explicit `Volumes`, `CapturedVolumes`, `Ports`, `Vsock`, `User`, and `LogLevel`. Image, replacement, and startup-command options are not accepted. Host resources remain unmapped unless explicitly supplied or `WithDangerouslyInheritResources()` is selected; `WithExternalMountPolicy` validates supplied filesystem mappings without granting access.

Destination controls use `WithRestoreCPUs(uint8)`, `WithRestoreMemory(uint32)` in MiB, `WithRestoreNetworkPolicy(*NetworkConfig)`, `WithRestoreMaxConnections(uint)`, `WithRestoreDisableNetwork()`, `WithRestoreSecurityProfile(SecurityProfile)`, `WithRestoreMaxDuration(time.Duration)`, and `WithRestoreIdleTimeout(time.Duration)`. These options also work with `RestoreSandboxWithProgress`. Network policy accepts the existing `NetworkPolicy` factory results, or `NetworkConfig` with only `Rules`, `DefaultEgress`, and `DefaultIngress`; other network fields are rejected rather than silently changing DNS, TLS, or bootstrap. Lifetime limits round up to whole seconds; explicit zero requests immediate expiry. Omit lifetime options or leave their `RestoreConfig` pointers `nil` for no limit by default. In contrast, `WithRestoreMaxConnections(0)` means no connection cap. Optional pointers distinguish omitted controls from explicit zero values.

Full execution restore requires CPU and memory overrides to match captured geometry exactly, and rejects removing a captured NIC. Host-side network policy, connection limits, and lifetime limits can change. An explicit security profile—including `SecurityProfileDefault`—requires a disk snapshot or `WithSnapshotDiskOnly()`; it cannot change already-captured execution.

## Snapshot groups

Installed snapshots belong to a group. A bare group selects its head; `group:member` selects a member by name or stable snapshot ID. Artifact paths remain valid selectors. Creation defaults to the source sandbox's group and generates a member name when empty; imports without a group create a new generated group. `DestDir` and `SnapshotLoadOptions.Dest` select the parent directory containing groups.

```go
snap, err := m.Snapshot.Create(ctx, m.SnapshotCreateOptions{
    Name: "baseline", FromSandbox: "box", Group: "work",
})
loaded, err := m.Snapshot.LoadWithOptions(ctx, "changes.msb", m.SnapshotLoadOptions{
    Base: "work:baseline", Group: "work",
})
head, err := m.Snapshot.GroupHead(ctx, "work")
selected, err := m.Snapshot.GroupHead(ctx, "work:baseline")
loaded, err = m.Snapshot.LoadWithOptions(ctx, "other.msb", m.SnapshotLoadOptions{
    Group: "work", SetHead: true,
})
```

`SnapshotLoadOptions` contains `Dest`, `Base`, `Group`, and `SetHead`. `Load` and `LoadWithBase` use generated groups. `GroupHead` returns `SnapshotHeadUpdate` with `Group`, `Previous`, `Head`, `Reason`, and `Changed`; `Previous` and `Head` are stable snapshot IDs. Automatic head updates initialize an empty group or advance to a proven descendant; divergent imports and imports with unknown ancestry retain the current head. Reasons are `initialized`, `fast_forwarded`, `selected`, `unchanged`, `diverged`, `unknown_ancestry`, and `ambiguous_candidates`. Direct archive capture creates no group and rejects a nonempty `Group`.

## Load multiple archives

```go
handles, err := m.Snapshot.LoadMany(ctx,
    []string{"changes.msb", "base.msb"},
    m.SnapshotLoadOptions{Group: "received"},
)
if err != nil { return err }
```

`LoadMany(ctx, archives []string, opts SnapshotLoadOptions)` returns `([]*SnapshotHandle, error)`, with one handle per supplied archive in input order. Dependencies are resolved regardless of argument order from the batch and exact matching snapshots already installed in an explicitly named destination group. `Base` supplies an external snapshot or standalone archive when needed. Single-file `LoadWithOptions` also reuses dependencies from its named destination group. An empty `Group` creates one generated group for the batch.

All batch members are validated before publication. `SetHead: true` requires a unique tip. With divergent tips and the default `false`, an existing head is retained (`ambiguous_candidates`); a new group has no head and imported handles return `nil` from `HeadUpdate()`. Select a member explicitly to give that group a head. The archive format is unchanged. The CLI equivalent is `msb snapshot load checkpoints/*.msb --group received`, with `--dest DIR` for another group-store root.

## Disk maintenance and incremental export

Exporting since a base omits reusable root/owned-disk layers and RAM objects. Every disk shared with the base must retain its exact physical prefix; compaction of any such disk requires a new standalone baseline. New owned disks are included completely. Owned directory namespaces stay complete while unchanged file payloads can come from the base. Full checkpoints keep the complete memory map and CPU/device state. The last-layers option selects only the newest root-disk layers, retaining complete owned disks and RAM payloads. Imports resolve dependencies from the batch or an explicitly named destination group. Use an external base for missing dependencies; direct restore still accepts an explicit base. Selective export cannot be combined with whole-group/with-parents export.

```go
worker, err := m.GetSandbox(ctx, "worker")
if err != nil { return err }
layers := uint32(3)
result, err := worker.Compact(ctx, m.DiskCompactionOptions{Layers: &layers})
if err != nil { return err }
err = m.Snapshot.Save(ctx, "worker:checkpoint-b", "changes.msb", m.SnapshotSaveOptions{Since: "worker:checkpoint-a"})
if err != nil { return err }
snapshot, err := m.Snapshot.LoadWithBase(ctx, "changes.msb", "", "worker:checkpoint-a")
```

Compaction defaults to the managed or flat root and all sandbox-owned data disks, never named/external disks or directories. Set `Disk: "/data"` to select one owned disk, or `RootDiskOnly: true` for only the root; these selectors are mutually exclusive. `Disk: "/"` also selects the root. `Layers` limits each disk to up to N oldest sealed physical layers including the base, excluding the writable head; N must be at least two. A nil `Layers` selects all sealed layers. Chains with fewer than two sealed layers are unchanged. `DryRun: true` only resolves the plan. Results contain aggregate metrics and per-disk `Disks` entries keyed by `GuestPath`. With no eligible disks the default succeeds with an empty list and zero layer and byte counts. Compaction requires a running or fully stopped local sandbox; multi-disk commits can require [journal-based recovery](/sandboxes/snapshots#export-changes-and-compact-a-disk-chain).

Per-disk `TotalUs` measures preparation/materialization only; aggregate `TotalUs` also includes journal adoption and backend switching, and `PauseUs` measures the shared VM pause. Timings are microseconds.

`LastLayers` is an alternative to `Since` for export. For direct restore use `RestoreSandbox(ctx, "changes.msb", "child", WithSnapshotBase("worker:checkpoint-a"))`. See [disk-chain maintenance](/sandboxes/snapshots#export-changes-and-compact-a-disk-chain) for dependency and retention rules.

`SnapshotArtifact.Path()` and `SnapshotHandle.Path()` remain available for local
snapshots. These accessors are deprecated and panic if no local filesystem path
exists. Use `Reference()` for backend-neutral code.

### SnapshotCreateOptions<span className="msb-tag is-type" style={{marginLeft: "8px"}}>struct</span>

<p className="msb-backref">Accepted by <a href="#snapshot-create">Snapshot.Create()</a></p>

Configures [`Snapshot.Create`](#snapshot-create). `FromSandbox` is required. An empty `Name` is generated; an empty `Group` uses the source sandbox's name.

| Field | Type | Description |
|-------|------|-------------|
| Name | `string` | Member name within its group; generated when empty |
| Group | `string` | Destination snapshot group; defaults to the source sandbox's name |
| FromSandbox | `string` | Name of the source sandbox; disk capture supports running, paused, stopped, and crashed sources |
| DestDir | `string` | Parent directory containing snapshot groups; empty = the default snapshots directory |
| Labels | `map[string]string` | Arbitrary user labels recorded in the manifest |
| Force | `bool` | Overwrite a direct archive output; rejected for installed group members |
| RecordIntegrity | `bool` | Record content hashes so [`Verify`](#s-verify) can recompute them later |
| Full | `bool` | Include memory and execution state from a running or paused source; `false` captures disk state from running, paused, stopped, or crashed sources |
