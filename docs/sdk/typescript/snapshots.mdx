## Sandbox capture

<span id="sandbox-group-capture" />

#### <span className="msb-recv">sandbox.</span><span className="msb-hn">snapshot()</span>

```typescript
snapshot(group: string): Promise<SnapshotCreateResult>
```

Create a group and its first disk checkpoint with default capture options. Available on `Sandbox` and `SandboxHandle`; an existing group is refused.

<span id="sandbox-group-capture-with" />

#### <span className="msb-recv">sandbox.</span><span className="msb-hn">snapshotWith()</span>

```typescript
snapshotWith(group: string, configure: (options: SnapshotCaptureOptions) => SnapshotCaptureOptions): Promise<SnapshotCreateResult>
```

Configure the initial member using [SnapshotCaptureOptions](#snapshot-capture-options). The sandbox receiver fixes the source.

<Accordion title="Example">

```typescript
import { Sandbox, Snapshot } from "microsandbox";

const source = await Sandbox.get("worker");
const created = await source.snapshotWith("history", capture =>
  capture.initialCheckpoint("ready").recordIntegrity());
const group = created.snapshot;
const next = await group.checkpointWith(capture => capture.name("after-build"));
const exact = await group.getCheckpoint("ready");
await group.setHead("ready");
await group.clearHead();
// Clearing selection keeps all checkpoints; use an exact member to spawn.
const child = await exact.spawnSandboxWith(destination => destination.name("child"));
const reopened = await Snapshot.get("history");
```

</Accordion>

Artifact helpers formerly owned by `Snapshot` are now accessed through `Checkpoint`. Existing `SnapshotHandle`, builder, archive, ID, and verification type names remain; this public object rename does not rewrite persisted artifact IDs. Retained artifact helpers below also cover supported cloud workflows, where local group operations return unsupported.

## Snapshot group methods

#### <span className="msb-recv">Snapshot.</span><span className="msb-hn">open()</span>

```ts
static open(path: string): Promise<Snapshot>
```

Open an existing local history directory, including groups captured or imported outside the default snapshot store. Relative paths are anchored when the call is made, before deferred work; symlinks retain their filesystem meaning. The returned group retains its backend and path for later operations. Missing directories fail without creating a group or falling back to a same-name default-store group. Cloud backends do not support this local-directory operation. Use `get` (`Get` in Go) to select a bare group name from the default store.

Capture the bound sandbox and return the exact checkpoint and this operation’s head outcome. Imported or orphaned groups refuse capture; a same-name replacement sandbox never becomes the source. ## Save an exact checkpoint

<Accordion title="Example">

```typescript
await checkpoint.save("ready.msb");
await checkpoint.saveWith("portable.msb", save => save.withParents().withImage());
```

</Accordion>

The receiver selects one immutable checkpoint. Use the group’s optional head or exact-member lookup first; saving a group’s whole history is not implied. The no-options call writes a compressed `.msb` archive. `saveTo` retains its explicit options form for compatibility. See the archive compatibility option below before sending output to an older reader.

## Group archive import

<span id="group-load" />

#### <span className="msb-recv">Snapshot.</span><span className="msb-hn">load()</span>

```typescript
static load(group: string, files: string[]): Promise<SnapshotImportResult>
```

Import a batch atomically using default storage and head policy.

<span id="group-load-with" />

#### <span className="msb-recv">Snapshot.</span><span className="msb-hn">loadWith()</span>

```typescript
static loadWith(group: string, files: string[], configure: (options: SnapshotLoadOptions) => SnapshotLoadOptions): Promise<SnapshotImportResult>
```

Configure dependency lookup, storage and selection with [SnapshotLoadOptions](#group-load-options).

<Accordion title="Example">

```typescript
await Snapshot.load(group, files);
await Snapshot.loadWith(group, files, load => load.destDir("store").base("base.msb").setHead());
```

</Accordion>

`files` is `string[]`. Returns `SnapshotImportResult`: `snapshot`, `checkpoints`, `added`, `reused`, `headUpdate`, `operationId`, and `warnings`.

The result contains every unique supplied checkpoint, including bundled dependencies, in stable ID order. `added` and `reused` identify what was new versus already installed at publication; archive argument order does not select the head. The head outcome belongs to this operation and does not change when another operation edits the group. Multiple incomparable tips can commit a headless group; explicit head selection refuses ambiguous tips.

A successful return confirms publication and catalog completion. Warnings describe deferred cleanup after commit. A structured import error distinguishes no publication, confirmed publication with a later failure, and an unknown outcome needing recovery. Import never binds a group to a source sandbox. See [atomic import requirements](/cli/snapshot-commands#msb-snap-import) for filesystem capabilities and maintenance requirements.

## Group inspection

<span id="group-inspect" />

#### <span className="msb-recv">group.</span><span className="msb-hn">inspect()</span>

```typescript
inspect(): Promise<SnapshotGroupInfo>
```

Returns the group's name, backend path, optional head, member count and optional saved source binding. Head and count come from one protected metadata read. Field names include `checkpointCount`, `source.recordedName`, `source.currentName`, `source.databaseUuid`, `source.sandboxId`. The source is absent for an unbound history; otherwise its status is `available`, `missing_sandbox` or `different_catalog`. Saved and current names distinguish renames; identity is the catalog UUID plus sandbox row ID, so deleting and recreating the same name does not rebind the group.

Source availability is observed separately from group metadata and is not a guarantee of later capture readiness. Inspection does not change the selected head or create a missing catalog identity. Invalid metadata and database failures remain errors, rather than being reported as unbound. Obtain a member with `getCheckpoint` for its immutable metadata.

## Group verification

<span id="group-verify" />

#### <span className="msb-recv">group.</span><span className="msb-hn">verify()</span>

```typescript
verify(): Promise<SnapshotGroupVerifyReport>
```

`await (await Snapshot.get("worker")).verify()` checks every pinned member and returns `SnapshotGroupVerifyReport`: `group`, `state`, `checkpoints`, and `payloadHashes`. States are `complete`, `incomplete`, `invalid`, or `empty`; an empty group explicitly means zero checkpoints checked. Each member has `id`, `path`, `state`, `report` (the existing `SnapshotVerifyReport`, or `null`), and specific `findings`. Shared physical files are hashed once per algorithm; independent copies are checked separately. Headless groups can be verified. To verify only head, obtain the optional checkpoint with `head()` and call its `verify()`.

Unrecorded checksums produce incomplete coverage. Corruption, missing files, unsupported requirements, and operational failures reject with `SnapshotVerificationError`, whose `report` retains all selected members and findings. Errors before a meaningful group report exists retain their ordinary error type. Cancellation does not release reader protection while hashing continues.

Selected members remain protected through hashing, including cancellation. Same-group captures, imports and head changes wait until verification finishes. Concurrent older removers must be stopped or upgraded; reads and sandbox execution can continue.

## Whole-group removal

<span id="group-remove" />

#### <span className="msb-recv">group.</span><span className="msb-hn">remove()</span>

```typescript
remove(): Promise<SnapshotRemoveResult>
```

Removes the selected history and returns `SnapshotRemoveResult` with `group`, `removed`, `headUpdate`, and `warnings`. The member IDs and cleared-head outcome belong to this operation. Empty groups can be removed. Active readers and surviving external dependents refuse removal; there is no force bypass for an entire group.

If publication commits but catalog cleanup fails, the call rejects with `SnapshotGroupRemovalRecoveryError` with `result` and `detail`. The attached result means removal already happened. Cleanup warnings after successful catalog reconciliation are returned in the result. An uncertain durability outcome is an error requiring recovery rather than a claimed successful removal. Later listing recovers pending cleanup without deleting a replacement group.

## Exact checkpoint removal

<Accordion title="Example">

```typescript
const removed = await checkpoint.remove();
const forced = await checkpoint.removeWith(options => options.force());
```

</Accordion>

These are alternative calls, not successive removals of the same checkpoint. The instance method removes the retained checkpoint identity, refuses a replacement at the same address, and returns `CheckpointRemoveResult` with `id`, optional `headUpdate`, and `warnings`. The head outcome belongs to this operation; later head edits do not change it. Removing the head selects its surviving same-group parent or clears selection. Removing another member reports an unchanged head. Standalone artifacts have no head outcome.

Force permits removal despite indexed children, but never bypasses reader protection. A repeated removal reports a missing checkpoint rather than fabricating another successful result. Backends or native libraries without exact-removal reporting return unsupported instead of falling back to deletion by name.

If removal commits but catalog cleanup fails, the call rejects with `SnapshotRemovalRecoveryError`, with `result` and `detail`. Its result is authoritative: removal already happened. Recover the affected storage before retrying cleanup; do not assume an error means the checkpoint still exists.

## Capture recovery

A failed capture can still have published its requested artifact before source recovery failed. `SnapshotSourceRecoveryError` preserves the source checkpoint recovery locator and, when publication completed, the published artifact’s kind, path, identity, digest and `headUpdate`. The head outcome belongs to that publication even if another operation changes the group afterward. Archive-only capture and older producers omit it; do not infer it by reading the current head. Inspect those details before retrying or removing the source. The error does not prove that the source is running or safely paused.

## Guest writeback

Use `.guestFlush("required")` on snapshot builders or `{ guestFlush: "required" }` in `source.fork`, `source.forkMany`, and `source.pause` options.

The default `"auto"` flushes live disk-only captures, but adds no optional flush to full captures, forks, or pause. `"skip"` retains mandatory storage barriers.

A paused disk capture needs a matching prior flush; cloud rejects non-Auto policies. See [guest flush policy reference](/sandboxes/snapshots#guest-flushing).

#### <span className="msb-recv">snap.</span><span className="msb-hn">verify()</span>

Check `report.coverage.kind` for `complete` or `incomplete` before treating all payloads as authenticated. Incomplete coverage lists required payload paths without recorded checksums, including ancestors and owned disks. The existing upper/head and checkpoint-root fields do not establish whole-artifact coverage. Corruption still raises an error. An older native library without coverage support reports `unknown`; a verified head is not promoted to complete coverage.

```typescript
verify(): Promise<SnapshotVerifyReport>
```

<Accordion title="Example">

```typescript
const report = await snap.verify();

  console.log(`hash matches: ${report.upper.digest}`);
} else {
  console.log("no integrity hash recorded");
}
```

</Accordion>

Verify the snapshot's complete state closure. File state recomputes recorded upper-layer integrity. Checkpoint state validates the complete checkpoint closure and returns its root in `report.checkpoint`.

## Forking

Fork a running or paused local sandbox to create a child with copy-on-write memory. The source returns to its previous state, and each child needs an unused name. `SandboxHandle` has the same methods. See the [forking guide](/sandboxes/snapshots#forking) for backend limits and disk bindings.

### fork()

```typescript
fork(name: string, options?: ForkOptions): Promise<Sandbox>
```

<Accordion title="Example">

```typescript
const child = await sandbox.fork("experiment");
try {
  console.log((await child.exec("python", ["-V"])).stdout);
} finally {
  await child.stop();
}
```

</Accordion>

Create one child from the current execution state.

### forkMany()

```typescript
forkMany(names: string[], options?: ForkOptions): Promise<ForkOutcome[]>
```

<Accordion title="Example">

```typescript
const outcomes = await sandbox.forkMany(["alice", "bob"]);
for (const outcome of outcomes) {
  if (outcome.sandbox) {
    await outcome.sandbox.stop();
  } else {
    console.error(outcome.name, outcome.error);
  }
}
```

</Accordion>

Capture once for all names and return outcomes in input order. Each outcome has `name` and either a started `sandbox` or an `error`. Validation or capture errors reject the whole call; a child startup error leaves successful siblings running. Stop successful children when finished.

### ForkOptions

```typescript
interface ForkOptions {
  recordIntegrity?: boolean;
  guestFlush?: GuestFlush;
  volumes?: Record<string, (mount: NapiMountBuilder) => NapiMountBuilder>;
}

type GuestFlush = "auto" | "required" | "skip";
```

`recordIntegrity` records disk hashes. [`guestFlush`](#guest-writeback) defaults to `"auto"`. Each `volumes` key is a captured disk's guest path; its callback configures the replacement mount. Forks cannot add new block devices, and batch children cannot share a writable disk image. See [fork disk bindings](/sandboxes/snapshots#forking). `branch()`, `branchMany()`, and `BranchOutcome` remain deprecated aliases.

## Compaction

Compact a local sandbox’s root or owned disks. See [compaction](/sandboxes/snapshots#compact-disks) for examples and recovery requirements.


<div className="msb-params">
  <div className="msb-param">
    <div className="msb-param-key"><code>disk</code></div>
    <div className="msb-param-desc">Select one owned disk by guest path; <code>/</code> selects the root.</div>
  </div>
  <div className="msb-param">
    <div className="msb-param-key"><code>rootDiskOnly</code></div>
    <div className="msb-param-desc">Select only the root. Cannot combine with the disk selector.</div>
  </div>
  <div className="msb-param">
    <div className="msb-param-key"><code>layers</code></div>
    <div className="msb-param-desc">Oldest sealed layers to merge, including the base. Minimum two; omit for all. Excludes the writable layer.</div>
  </div>
  <div className="msb-param">
    <div className="msb-param-key"><code>dryRun</code></div>
    <div className="msb-param-desc">Preview without changing storage.</div>
  </div>
</div>

Defaults to the root and owned data disks; excludes named/external volumes and directories. Requires a running or fully stopped local sandbox. Fewer than two sealed layers means no change; no eligible disks returns an empty result with zero counts.

Results include aggregate counts and per-disk entries keyed by `guestPath`. `materializedBytes` counts copied bytes, not reclaimed space. Times are microseconds: per-disk `totalUs` covers preparation; aggregate `totalUs` also includes switching; `pauseUs` measures the shared VM pause.
