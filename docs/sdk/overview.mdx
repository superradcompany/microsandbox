The SDK runs microsandbox directly from your application. Running locally, creating a sandbox spawns a VM as a child process; there is no daemon to install and no server to connect to. Use an explicit `RemoteContext` to run sandboxes on [microsandbox cloud](/cloud/overview) or another compatible remote API. See [contexts](/operations/backends#sdk-contexts) for destination selection.

## Installation

<CodeGroup>
```bash TypeScript
npm install microsandbox
```

```bash Rust
cargo add microsandbox
```

```bash Python
pip install microsandbox
```

```bash Go
go get github.com/superradcompany/microsandbox/sdk/go
```

```bash Ruby
gem install microsandbox
```
</CodeGroup>

## Select a smaller distribution

The full `microsandbox` package remains available. TypeScript and Python also have separate local and remote packages that include only their selected native binding. These lean packages do not include `msb`, firmware, a runtime launcher, or an automatic runtime download during installation.

For a remote API:

<CodeGroup>
```bash TypeScript
npm install @microsandbox/remote
```

```bash Python
pip install microsandbox-remote
```
</CodeGroup>

<CodeGroup>
```typescript TypeScript
import { RemoteContext } from "@microsandbox/remote";

const remote = RemoteContext.builder()
  .url("https://api.microsandbox.dev")
  .apiKey(process.env.MSB_API_KEY!)
  .build();
const sb = await remote.sandboxes.get("worker");
console.log(await sb.status());
```

```python Python
import asyncio
import os
from microsandbox_remote import RemoteContext

async def main():
    remote = RemoteContext(api_key=os.environ["MSB_API_KEY"])
    sb = await remote.sandboxes.get("worker")
    print(await sb.status())

asyncio.run(main())
```
</CodeGroup>

For local execution with a [separately provisioned runtime](/sdk/setup#bring-your-own-runtime), install `@microsandbox/local` or `microsandbox-local`. Import `Sandbox` from that package and use the ordinary default-local factories shown below. Explicit `LocalContext` is needed only for custom local configuration.

Go also supports thin `sdk/go/local` and `sdk/go/remote` modules over the common `sdk/go/core` module. They do not embed the FFI. Provision the selected native library explicitly before constructing a context:

```bash
go get github.com/superradcompany/microsandbox/sdk/go/remote
# Use the exact SDK version, artifact URL and SHA-256 from the trusted release.
go run github.com/superradcompany/microsandbox/sdk/go/core/cmd/ffi-setup@VERSION \
  --kind remote --source EXACT_ARTIFACT_URL --sha256 TRUSTED_SHA256
```

```go
import (
    "context"
    "os"

    "github.com/superradcompany/microsandbox/sdk/go/remote"
)

// An empty path selects the verified install cache; a path selects a trusted offline library.
destination, err := remote.NewContext("", "https://api.microsandbox.dev", os.Getenv("MSB_API_KEY"))
if err != nil { return err }
sb, err := destination.Sandboxes().Get(context.Background(), "worker")
if err != nil { return err }
defer sb.Close()
```

Go setup accepts an offline native file through `--source` too. `--target` permits cross-target provisioning without loading the library. Neither module installation, import, nor first use downloads FFI or runtime files. Local execution still needs a separately provisioned runtime pair.

Both providers can be installed in one application. They share the public `Sandbox`, `Volume`, `Snapshot`, configuration and error types; each resource retains its selected provider. Installing a remote provider does not redirect default-local factories. A missing provider produces an installation error when selected.

## Small example

Create a sandbox from a container image, run a command, print the output, and remove it.

<CodeGroup>
```typescript TypeScript
import { Sandbox } from "microsandbox";

const sb = await Sandbox.builder("hello")
    .image("python")
    .create();

try {
    const output = await sb.exec("python", ["-c", "print('Hello, World!')"]);
    console.log("Output:", output.stdout());
} finally {
    await sb.stop();
    await Sandbox.remove("hello");
}
```

```rust Rust
use std::error::Error;

use microsandbox::Sandbox;

#[tokio::main]
async fn main() -> Result<(), Box<dyn Error>> {
    let sb = Sandbox::builder("hello")
        .image("python")
        .create()
        .await?;

    let output = sb.exec("python", ["-c", "print('Hello, World!')"]).await?;
    println!("{}", output.stdout()?);

    sb.stop().await?;
    Sandbox::remove("hello").await?;
    Ok(())
}
```

```python Python
import asyncio
from microsandbox import Sandbox

async def main():
    sb = await Sandbox.create(
        "hello",
        image="python",
    )

    output = await sb.exec("python", ["-c", "print('Hello, World!')"])
    print("Output:", output.stdout_text)

    await sb.stop()
    await Sandbox.remove("hello")

asyncio.run(main())
```

```go Go
package main

import (
    "context"
    "fmt"
    "log"

    m "github.com/superradcompany/microsandbox/sdk/go"
)

func main() {
    if err := run(); err != nil {
        log.Fatal(err)
    }
}

func run() error {
    ctx := context.Background()

    if _, err := m.EnsureRuntime(ctx, m.RuntimeConfig{}, m.InstallOptions{}); err != nil {
        return err
    }

    sb, err := m.CreateSandbox(ctx, "hello", m.WithImage("python"))
    if err != nil {
        return err
    }
    defer func() {
        _ = sb.Stop(context.Background())
        _ = sb.Close()
        _ = m.RemoveSandbox(context.Background(), "hello")
    }()

    out, err := sb.Exec(ctx, "python", []string{"-c", "print('Hello, World!')"})
    if err != nil {
        return err
    }
    fmt.Println("Output:", out.Stdout())
    return nil
}
```

```ruby Ruby
require "microsandbox"

Microsandbox.install unless Microsandbox.installed?

Microsandbox::Sandbox.with("hello", image: "python") do |sandbox|
  output = sandbox.exec("python", ["-c", "print('Hello, World!')"])
  puts "Output: #{output.stdout}"
end
Microsandbox::Sandbox.remove("hello")
```

</CodeGroup>
