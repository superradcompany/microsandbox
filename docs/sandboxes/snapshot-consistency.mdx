Snapshots can preserve files on disk or include the memory of a running workload. Writes buffered in memory need different handling when you restore only the disks. These rules apply equally to the CLI and all SDKs.

## Guest flushing

Guest flushing writes the sandbox's filesystem caches to its persistent disks before capture or pause. It covers the root and captured block disks, including owned disks. It does not flush application-owned buffers, commit database transactions, or make tmpfs persistent; coordinate those with your application when needed.

Keep the default `auto` policy for normal captures. It flushes running disk-only captures. Full snapshots and branches preserve buffered writes in memory, so they do not request this extra flush by default.

Use `required` when you need a full snapshot's disks to include those writes even if you later restore without its memory. For a running local sandbox named `worker`:

<CodeGroup>
```typescript TypeScript
import { Snapshot } from "microsandbox";

const snapshot = await Snapshot.builder("ready")
    .fromSandbox("worker")
    .full()
    .guestFlush("required")
    .create();
```

```rust Rust
use microsandbox::{snapshot::GuestFlush, Snapshot};

let snapshot = Snapshot::builder("ready")
    .from_sandbox("worker")
    .full()
    .guest_flush(GuestFlush::Required)
    .create()
    .await?;
```

```python Python
from microsandbox import GuestFlush, Snapshot

snapshot = await Snapshot.create(
    "ready",
    from_sandbox="worker",
    full=True,
    guest_flush=GuestFlush.REQUIRED,
)
```

```go Go
import m "github.com/superradcompany/microsandbox/sdk/go"

snapshot, err := m.Snapshot.Create(ctx, m.SnapshotCreateOptions{
    Name:        "ready",
    FromSandbox: "worker",
    Full:        true,
    GuestFlush:  m.GuestFlushRequired,
})
if err != nil { return err }
```

```bash CLI
msb snap create ready --sandbox worker --full --guest-flush required
```
</CodeGroup>

The same policy is available when branching or pausing. See the [TypeScript](/sdk/typescript/snapshots#guest-writeback), [Rust](/sdk/rust/snapshots#guest-writeback), [Python](/sdk/python/snapshots#guest-writeback), [Go](/sdk/go/snapshots#guest-writeback), and [CLI](/cli/sandbox-commands#msb-pause-resume) references for the corresponding options. Cloud supports only `auto`.

<Accordion title="Advanced flush behavior">

| Policy | Running disk-only capture | Full capture, branch, or pause |
| --- | --- | --- |
| `auto` (default) | Require guest writeback | No optional filesystem flush |
| `required` | Require guest writeback | Also flush captured persistent filesystems |
| `skip` | Capture unflushed disk state | No optional guest writeback |

With `skip`, a disk-only snapshot may omit buffered writes and need filesystem recovery. Full snapshots and branches preserve those writes in RAM. Every policy still enforces host-backed directory synchronization, host disk-I/O draining, and snapshot durability.

A paused source must have acknowledged any required flush before pausing. Capture fails rather than resuming it to flush. To prepare for a disk snapshot, pause with `required`, capture while paused, then resume. The same sequence applies through the CLI or an SDK.

For stopped or crashed sources, `auto` and `skip` capture existing disk state; `required` fails because no guest is running. Older runtimes that cannot enforce a requested policy reject it before capture; restart the source with the updated runtime.

</Accordion>
