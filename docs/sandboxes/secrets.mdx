Secrets let sandboxed code call APIs without holding the real credentials. Credentials stay on the host; the guest receives a placeholder in an environment variable. When a request goes to an allowed host, microsandbox verifies the destination and replaces the placeholder with the real credential at the network boundary.

## Add a secret

Bind `GITHUB_TOKEN` to `api.github.com` when creating the sandbox. Set the real token in your host environment before running the example.

<CodeGroup>
```typescript TypeScript
import { Sandbox } from "microsandbox";

await using sb = await Sandbox.builder("worker")
    .image("python")
    .secret((s) =>
        s.env("GITHUB_TOKEN")
            .value(process.env.GITHUB_TOKEN!)
            .allowHost("api.github.com"),
    )
    .create();
```

```rust Rust
use microsandbox::Sandbox;

let sb = Sandbox::builder("worker")
    .image("python")
    .secret(|s| s
        .env("GITHUB_TOKEN")
        .value(std::env::var("GITHUB_TOKEN")?)
        .allow_host("api.github.com")
    )
    .create()
    .await?;
```

```python Python
import os
from microsandbox import Sandbox, Secret

sb = await Sandbox.create(
    "worker",
    image="python",
    secrets=[
        Secret.env(
            "GITHUB_TOKEN",
            value=os.environ["GITHUB_TOKEN"],
            allow_hosts=["api.github.com"],
        ),
    ],
)
```

```go Go
sb, err := m.CreateSandbox(ctx, "worker",
    m.WithImage("python"),
    m.WithSecrets(
        m.Secret.Env("GITHUB_TOKEN", os.Getenv("GITHUB_TOKEN"),
            m.SecretEnvOptions{
                AllowHosts:  []string{"api.github.com"},
            },
        ),
    ),
)
```

```bash CLI
msb create python --name worker \
  --secret "GITHUB_TOKEN@api.github.com"
```

</CodeGroup>

The guest sees `$MSB_GITHUB_TOKEN`. The default placeholder is `$MSB_<env_var>`; SDKs also support custom placeholders.

<Warning>
  SDK examples that pass a raw value save it in the host-side sandbox configuration. The CLI's `ENV@HOST` form stores a reference and reads its value when the sandbox starts; inline `ENV=VALUE@HOST` is rejected.
</Warning>

## Use it in a request

Inside the sandbox, use the environment variable as the credential. For example, with Python's standard library:

```python
import os
import urllib.request

request = urllib.request.Request(
    "https://api.github.com/user",
    headers={"Authorization": f"Bearer {os.environ['GITHUB_TOKEN']}"},
)
with urllib.request.urlopen(request) as response:
    print(response.read().decode())
```

The request starts with the placeholder. At the network boundary, microsandbox verifies the destination and injects the real token. Printing the environment variable inside the sandbox still shows only the placeholder.

Substitution requires intercepted TLS by default. Headers and Basic auth are enabled; query parameters and request bodies require explicit SDK configuration. Bypassed TLS cannot use secret injection. See [TLS inspection](/networking/tls) and the [injection options](/sdk/typescript/secrets#secretinjection).

## Violation policy

When an inspected request contains a placeholder for a destination that cannot receive the credential, microsandbox blocks it and logs a warning by default.

| Action | Result |
| --- | --- |
| `block-and-log` (default) | Block the request and log a warning. |
| `block` | Block without a violation log. |
| `block-and-terminate` | Block, log an error, and stop the sandbox. |
| `passthrough` | Forward the placeholder unchanged to permitted hosts. |

For example, stop the sandbox if it sends this secret's placeholder to a disallowed host:

<CodeGroup>
```typescript TypeScript
import { Sandbox } from "microsandbox";

await using sb = await Sandbox.builder("worker")
    .image("python")
    .secret((s) =>
        s.env("GITHUB_TOKEN")
            .value(process.env.GITHUB_TOKEN!)
            .allowHost("api.github.com")
            .onViolation((v) => v.blockAndTerminate()),
    )
    .create();
```

```rust Rust
use microsandbox::Sandbox;

let sb = Sandbox::builder("worker")
    .image("python")
    .secret(|s| s
        .env("GITHUB_TOKEN")
        .value(std::env::var("GITHUB_TOKEN")?)
        .allow_host("api.github.com")
        .on_violation(|v| v.block_and_terminate())
    )
    .create()
    .await?;
```

```python Python
import os
from microsandbox import Sandbox, Secret, ViolationAction

sb = await Sandbox.create(
    "worker",
    image="python",
    secrets=[
        Secret.env(
            "GITHUB_TOKEN",
            value=os.environ["GITHUB_TOKEN"],
            allow_hosts=["api.github.com"],
            on_violation=ViolationAction.BLOCK_AND_TERMINATE,
        ),
    ],
)
```

```go Go
sb, err := m.CreateSandbox(ctx, "worker",
    m.WithImage("python"),
    m.WithSecrets(
        m.Secret.Env("GITHUB_TOKEN", os.Getenv("GITHUB_TOKEN"),
            m.SecretEnvOptions{
                AllowHosts:  []string{"api.github.com"},
                OnViolation: m.ViolationActionBlockAndTerminate,
            },
        ),
    ),
)
```

```bash CLI
msb create python --name worker \
  --secret "GITHUB_TOKEN@api.github.com" \
  --on-secret-violation block-and-terminate
```

</CodeGroup>

The SDK examples set a per-secret action. The CLI flag sets the sandbox-wide action. SDKs also expose a sandbox-wide default through networking configuration; an explicit per-secret action overrides it.

<Accordion title="Let selected hosts receive the placeholder">
  Passthrough lets a host receive the placeholder without receiving the credential. It does not grant network access or add that host to the substitution allow list.

  Configure host-scoped passthrough with [TypeScript](/sdk/typescript/secrets#violationactionbuilder), [Rust](/sdk/rust/networking#violationactionbuilder), or [Python](/sdk/python/secrets#violationpolicy). The Go SDK does not expose host-scoped passthrough. CLI `--on-secret-violation passthrough` applies to all hosts.

  A per-secret passthrough rule falls back to the sandbox-wide policy for unmatched hosts. An unmatched sandbox-wide passthrough rule falls back to `block-and-log`.
</Accordion>

## Update secrets

<Tooltip tip="modify is not yet available on microsandbox cloud; recreate the sandbox to change its secrets."><span className="msb-badge-local">Local-only <Icon icon="circle-info" size={11} /></span></Tooltip>
Rotate or remove an existing secret without restarting. Adding a secret or changing its placeholder requires a restart. The examples below allow a restart if needed and read the replacement value from the host environment.

Updating or removing a sandbox secret does not rotate or revoke the credential at its provider. Do that separately with GitHub or the service that issued it.

<CodeGroup>
```typescript TypeScript
await sb.modify({
  secrets: {
    GITHUB_TOKEN: { env: "GITHUB_TOKEN", allowedHosts: ["api.github.com"] },
  },
  policy: "restart",
});

await sb.modify({ secretsRemove: ["GITHUB_TOKEN"] });
```

```rust Rust
use microsandbox::SecretSource;

let plan = sb.modify()
    .secret(|s| s
        .env("GITHUB_TOKEN")
        .source(SecretSource::Env { var: "GITHUB_TOKEN".into() })
        .allow_host("api.github.com"))
    .restart()
    .apply()
    .await?;

sb.modify().remove_secret("GITHUB_TOKEN").apply().await?;
```

```python Python
from microsandbox import ModificationPolicy

await sb.modify(
    secrets={
        "GITHUB_TOKEN": {
            "env": "GITHUB_TOKEN",
            "allowed_hosts": ["api.github.com"],
        },
    },
    policy=ModificationPolicy.RESTART,
)

await sb.modify(secrets_rm=["GITHUB_TOKEN"])
```

```go Go
_, err := sb.Modify(ctx, m.ModifyOptions{
    Secrets: map[string]m.SecretModifySpec{
        "GITHUB_TOKEN": {
            Env:          "GITHUB_TOKEN",
            AllowedHosts: []string{"api.github.com"},
        },
    },
    Policy: m.ModificationPolicyRestart,
})

_, err = sb.Modify(ctx, m.ModifyOptions{
    SecretsRemove: []string{"GITHUB_TOKEN"},
})
```

```bash CLI
msb modify worker --secret GITHUB_TOKEN@api.github.com --restart  # add or rotate
msb modify worker --secret-rm GITHUB_TOKEN                       # remove
```
</CodeGroup>

See [Live Modify](/sandboxes/tuning) for update behavior and restart policies.

## Troubleshooting

| Symptom | Check |
| --- | --- |
| A request fails | Check host logs for a violation warning and verify the allowed host, including redirect destinations. |
| The sandbox stops after a request | Check for `block-and-terminate`. |
| The API receives a placeholder or rejects authentication | Check TLS interception, the allowed host, injection location, and any passthrough rule. |
| The guest prints `$MSB_GITHUB_TOKEN` | Expected: substitution happens only at the network boundary. |

## Security and reference

Secret host rules control credential injection; network rules control access. Allowing a host to receive a secret does not grant network access to it.

Keep allowed hosts narrow: they receive the real credential and must be trusted not to return it to the guest. A wildcard such as `*.example.com` includes the root domain and its subdomains.

Secrets do not provide raw credentials for guest-side operations such as signing requests. A plain environment variable containing the real token exposes it to guest code. See [Secret handling](/security/secrets) for the protection boundary and storage details.

For API options, see [TypeScript](/sdk/typescript/secrets), [Rust](/sdk/rust/secrets), [Python](/sdk/python/secrets), [Go](/sdk/go/secrets), or [CLI configuration](/cli/configuration#secrets).
