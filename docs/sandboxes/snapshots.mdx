<Tooltip tip="Cloud supports disk snapshots from stopped or crashed sandboxes and disk restore. Full snapshots, branching, groups, and local archives are not yet available on cloud."><span className="msb-badge-limited">Limited on cloud <Icon icon="circle-info" size={11} /></span></Tooltip>

Save a prepared sandbox and reuse it as a starting point. Each restore creates a new sandbox and leaves the source unchanged.

## Snapshot types

Disk is the default. Full adds memory and execution state; there is no memory-only snapshot.

| Type | Saves | On restore |
| --- | --- | --- |
| **Disk** | Files and owned volumes | Boots a new VM |
| **Full** | Disk, memory, and running processes | Resumes execution |

## Disk snapshots

Use disk snapshots for installed dependencies, prepared workspaces, and saved files. Local live captures flush guest filesystem writes by default; application buffers and transactions still need application-level coordination. Cloud requires a stopped or crashed source. See [guest filesystem flush](#guest-filesystem-flush) for paused sources and the unflushed `skip` policy.

<Steps>
<Step title="Prepare">

```typescript TypeScript
const session = await baseline.connect();
await session.exec("pip", ["install", "requests"]);

await baseline.stop();
```

## Full snapshots

<Tooltip tip="Full snapshots are not yet available on microsandbox cloud."><span className="msb-badge-local">Local-only <Icon icon="circle-info" size={11} /></span></Tooltip>

Capture a running workload to resume its processes and memory later. A running source briefly pauses during capture, then resumes; an already-paused source stays paused.

<Steps>
<Step title="Capture">

<CodeGroup>

```typescript TypeScript
    .full()
    .create();
```

```rust Rust

    .from_sandbox("worker")
    .full()
    .create()

```

```python Python
    full=True,
)
```

```go Go

    Name:        "snap",
    FromSandbox: "worker",

```

```bash CLI
msb snapshot create snap --from-sandbox worker --full
```
</CodeGroup>

</Step>
<Step title="Restore">

<CodeGroup>
```typescript TypeScript

    .name("resumed")
    .restore();
```

```rust Rust

    .name("resumed")
    .restore()
    .await?;
```

```python Python

```

```go Go

if err != nil { return err }
```

```bash CLI
msb restore worker:snap --name resumed
```
</CodeGroup>

</Step>
</Steps>

- **Compatibility:** Use a compatible runtime and guest kernel. CPU and memory settings, including maximums, must match the capture.
- **Connections:** Reconnect clients and application connections. Host-side connections and transfers are not captured; buffered process output is not replayed.
- **Mounts:** Owned volumes are private to each child. Host bindings need explicit authorization; see [mount behavior](#mount-behavior).

<Accordion title="Capture or restore fails">

If capture saves an artifact but cannot recover the source, inspect the artifact reported in the error before retrying. A packaging failure may leave only a runtime checkpoint.

If restore leaves an incomplete child, remove it and restore again; the snapshot remains reusable. Older development full snapshots may need recapture or disk-only restore.

</Accordion>

### Share memory

Full restores normally copy memory. Enable copy-on-write (CoW) to share unchanged pages between children while keeping writes private:

<CodeGroup>
```typescript TypeScript
const worker_a = await Sandbox.restore("worker:snap")
    .name("worker_a")
    .forked()
    .restore();

const worker_b = await Sandbox.restore("worker:snap")
    .name("worker_b")
    .forked()
    .restore();
```

```rust Rust
let worker_a = Sandbox::restore("worker:snap")
    .name("worker_a")
    .forked()
    .restore()
    .await?;

let worker_b = Sandbox::restore("worker:snap")
    .name("worker_b")
    .forked()
    .restore()
    .await?;
```

```python Python
worker_a = await Sandbox.restore(
    "worker:snap",
    name="worker_a",
    forked=True,
)

worker_b = await Sandbox.restore(
    "worker:snap",
    name="worker_b",
    forked=True,
)
```

```go Go
worker_a, err := m.RestoreSandbox(ctx, "worker:snap", "worker_a",
    m.WithForked(),
)
if err != nil { return err }

worker_b, err := m.RestoreSandbox(ctx, "worker:snap", "worker_b",
    m.WithForked(),
)
if err != nil { return err }
```

```bash CLI
msb restore worker:snap --name worker_a --forked
msb restore worker:snap --name worker_b --forked
```
</CodeGroup>

The first restore prepares a local memory cache; later restores reuse it. No special source setup is needed. CoW requires a full snapshot and cannot be combined with disk-only restore.

### Restore disk only

Boot from a full snapshot’s saved disk without resuming its processes. This allows different CPU and memory settings and needs no compatible memory codec.

<CodeGroup>
```typescript TypeScript
const rebooted = await Sandbox.restore("worker:snap")
    .name("rebooted")
    .diskOnly()
    .restore();
```

```rust Rust
let rebooted = Sandbox::restore("worker:snap")
    .name("rebooted")
    .disk_only()
    .restore()
    .await?;
```

```python Python
rebooted = await Sandbox.restore(
    "worker:snap",
    name="rebooted",
    disk_only=True,
)
```

```go Go
rebooted, err := m.RestoreSandbox(ctx, "worker:snap", "rebooted",
    m.WithSnapshotDiskOnly(),
)
if err != nil { return err }
```

```bash CLI
msb restore worker:snap --name rebooted --disk-only
```
</CodeGroup>

Disk-only restore copies only the checkpoint's disk chain, creates a fresh writable qcow2 head, and performs an ordinary boot. It does not require the destination to support the checkpoint's memory or execution codec. The disk projection of a full snapshot may omit writes buffered in guest RAM unless capture used `--guest-flush required`; filesystem journal recovery may still run. Full restore preserves those buffers in RAM. Host disk flushes and durable snapshot publication remain enforced regardless of guest-flush policy. A tmpfs-root snapshot cannot restore disk-only.

## Guest filesystem flush

`--guest-flush auto|required|skip` controls guest writeback for the root and captured block disks, including owned disks, during snapshot creation, branching, and pause. Host-backed directories (owned directories and external virtiofs mounts) retain their synchronization barriers. Host disk-I/O draining and snapshot durability are unchanged.

| Policy | Live disk-only snapshot | Full snapshot, branch, or pause |
| --- | --- | --- |
| `auto` (default) | Require guest writeback | Preserve dirty pages in RAM; no block-filesystem flush |
| `required` | Require guest writeback | Also flush captured persistent filesystems |
| `skip` | Accept unflushed disk state | No optional guest writeback |

Use `required` on a full snapshot when you also want to restore its disks without RAM. Flushing writes the guest filesystem cache, not application buffers or transactions. It also does not make tmpfs persistent.

`skip` on a disk-only snapshot accepts crash-consistent root and owned disks: recent buffered writes may be absent and filesystem recovery may be needed. Full snapshots and branches retain those dirty pages in captured RAM. An owned disk does not force guest writeback during plain pause. Earlier guest-flush builds flushed root and owned disks unconditionally when any owned mount existed; do not rely on that incidental behavior with `skip`.

```bash
msb snapshot create disk --from-sandbox worker
msb snapshot create full --from-sandbox worker --full --guest-flush required
msb branch worker --name child --guest-flush skip

# Prepare a flush boundary before pausing; capture keeps the source paused.
msb pause worker --guest-flush required
msb snapshot create paused --from-sandbox worker
msb resume worker
```

A paused source must already have acknowledged the required flush at that pause. Otherwise capture fails without resuming it. For a stopped or crashed source, `auto` and `skip` capture existing disk state; `required` fails because no guest is running. Older runtimes that cannot enforce a requested policy reject it before capture; restart the source with the updated runtime.

SDK equivalents use the same policy:

<CodeGroup>
```typescript TypeScript
await Snapshot.builder("full").fromSandbox("worker").full().guestFlush("required").create();
await source.pause({ guestFlush: "required" });
await source.branchMany(["alice", "bob"], { guestFlush: "skip" });
```

```rust Rust
use microsandbox::{Snapshot, snapshot::GuestFlush};
Snapshot::builder("full").from_sandbox("worker").full()
    .guest_flush(GuestFlush::Required).create().await?;
source.pause_with_guest_flush(GuestFlush::Required).await?;
```

```python Python
from microsandbox import GuestFlush, Snapshot
await Snapshot.create("full", from_sandbox="worker", full=True, guest_flush=GuestFlush.REQUIRED)
await source.pause(guest_flush=GuestFlush.REQUIRED)
```

```go Go
snapshot, err := msb.Snapshot.Create(ctx, msb.SnapshotCreateOptions{
    Name: "full", FromSandbox: "worker", Full: true, GuestFlush: msb.GuestFlushRequired,
})
err = source.PauseWithGuestFlush(ctx, msb.GuestFlushRequired)
child, err := source.Branch(ctx, "child", msb.WithBranchGuestFlush(msb.GuestFlushSkip))
```
</CodeGroup>

## Branching

<Tooltip tip="Branching is not yet available on microsandbox cloud."><span className="msb-badge-local">Local-only <Icon icon="circle-info" size={11} /></span></Tooltip>

Create a child directly from a running or paused sandbox, without saving a reusable snapshot. Like full restore, branching preserves disk and execution state. Memory sharing is built in; each child’s writes stay private.

<CodeGroup>
```typescript TypeScript
const source = await Sandbox.get("worker");

const experiment = await source.branch("experiment");
```

```rust Rust
let source = Sandbox::get("worker").await?;

let experiment = source.branch("experiment").branch().await?;
```

```python Python
source = await Sandbox.get("worker")

experiment = await source.branch("experiment")
```

```go Go
source, err := m.GetSandbox(ctx, "worker")
if err != nil { return err }

experiment, err := source.Branch(ctx, "experiment")
if err != nil { return err }
```

```bash CLI
msb branch worker --name experiment
```
</CodeGroup>

The source returns to its previous running or paused state. Each child needs a new name and cannot inherit published host ports. Host mounts follow the same [binding rules](#external-mounts).

<Accordion title="Create several children">

Capture once for several children:

<CodeGroup>
```typescript TypeScript
const source = await Sandbox.get("worker");

const children = await source.branchMany(["alice", "bob"]);
```

```rust Rust
let source = Sandbox::get("worker").await?;

let children = source.branch_many(["alice", "bob"]).branch().await?;
```

```python Python
source = await Sandbox.get("worker")

children = await source.branch_many(["alice", "bob"])
```

```go Go

if err != nil { return err }

children, err := source.BranchMany(ctx, []string{"alice", "bob"})
if err != nil { return err }
```

```bash CLI
msb branch worker --names alice bob
```
</CodeGroup>

Each child gets its own result; a failed child does not remove successful siblings. Validation or capture errors fail the call. Deleting the source or a sibling does not invalidate other children.

</Accordion>

## Mount behavior

| State | Disk snapshot | Full snapshot |
| --- | --- | --- |
| Owned volume contents | Private copy per child | Private copy per child |
| Host bind-mount files | External; not copied | External; not copied |
| Open handles and caches | Processes start fresh | Supported state resumes |

Owned directory snapshots cannot move between Unix and Windows. Owned disks do not have this restriction.

### External mounts

Full restore requires bindings for captured external filesystems and additional disks. Supply `-v /host/data:/data`, select a private captured disk with `-v /data`, or explicitly authorize validated source-local bindings with `--dangerously-inherit-resources`. Inheritance is not permission to ignore a missing dependency. Owned volumes are reconstructed automatically.

Use `--allow-missing-resources` to resume with unavailable resources and warnings; their backend operations return `EIO`. This does not inherit resources or accept changed objects in a supplied mapping. SDK equivalents are Rust `.allow_missing_resources()`, Python `allow_missing_resources=True`, TypeScript `.allowMissingResources()`, and Go `WithAllowMissingResources()`. Direct branches retain their existing omission behavior. Disk-only restore is a cold boot, not restoration of captured external filesystem handles.

These explicit bindings work for disk and full snapshots:

<CodeGroup>
```typescript TypeScript
const child = await Sandbox.restore("worker:snap")
    .name("child")
    .volume("/work", v => v.bind("/host/project"))
    .restore();
```

```rust Rust
let child = Sandbox::restore("worker:snap")
    .name("child")
    .volume("/work", |v| v.bind("/host/project"))
    .restore()
    .await?;
```

```python Python
from microsandbox import Sandbox, Volume

child = await Sandbox.restore(
    "worker:snap",
    name="child",
    volumes={"/work": Volume.bind("/host/project")},
)
```

```go Go
child, err := m.RestoreSandbox(ctx, "worker:snap", "child",
    m.WithRestoreConfig(m.RestoreConfig{
        Volumes: map[string]m.MountConfig{
            "/work": m.Mount.Bind("/host/project", m.MountOptions{}),
        },
    }))
if err != nil { return err }
```

```bash CLI
msb restore worker:snap --name child -v /host/project:/work
```
</CodeGroup>

Mapping source and child to the same host directory shares files. Named disk volumes restore privately; arbitrary external disk images are not converted to owned volumes.

### Validate mounts

Full restore and branching validate captured filesystem identities. Strict is the default; relaxed mode accepts supported differences and reports warnings:

<CodeGroup>
```typescript TypeScript
const child = await Sandbox.restore("worker:snap")
    .name("child")
    .volume("/work", v => v.bind("/host/copy"))
    .externalMountPolicy("relaxed")
    .restore();
```

```rust Rust
use microsandbox::ExternalMountRestorePolicy;

let child = Sandbox::restore("worker:snap")
    .name("child")
    .volume("/work", |v| v.bind("/host/copy"))
    .external_mount_policy(ExternalMountRestorePolicy::Relaxed)
    .restore()
    .await?;
```

```python Python
from microsandbox import Sandbox, Volume

child = await Sandbox.restore(
    "worker:snap",
    name="child",
    volumes={"/work": Volume.bind("/host/copy")},
    external_mount_policy="relaxed",
)
```

```go Go
child, err := m.RestoreSandbox(ctx, "worker:snap", "child",
    m.WithRestoreConfig(m.RestoreConfig{
        Volumes: map[string]m.MountConfig{
            "/work": m.Mount.Bind("/host/copy", m.MountOptions{}),
        },
    }),
    m.WithExternalMountPolicy(m.ExternalMountRelaxed))
if err != nil { return err }
```

```bash CLI
msb restore worker:snap --name child \
    -v /host/copy:/work --external-mount-policy relaxed
```
</CodeGroup>

Relaxed mode validates supplied filesystem objects; it does not grant host access, waive missing-resource checks, recreate missing files, or bypass integrity checks. Full restore requires `--allow-missing-resources` to leave an external filesystem or additional disk unavailable. Root and owned storage must still be complete. Direct branching retains its existing unavailable-resource behavior. Backend I/O returns errors for unavailable devices, which can abort filesystem journals or make them read-only; warnings remain visible with `--quiet`.

<Accordion title="Open files and cached data">

Full snapshots retain clean cache pages, so reads may return captured bytes before reaching the host. Strict validation checks identity at restore time; it does not lock files against later edits.

External files deleted while still open, and special files, can prevent capture. Owned directories support deleted open regular files. Restore warnings identify inaccessible or changed objects; see your [SDK reference](#reference) for details.

</Accordion>

## Manage snapshots

These operations apply to disk and full snapshots. Cloud supports basic disk snapshot management; groups, archives, verification, and disk maintenance below are local-only.

### Restore progress

Track local disk or full restore through image preparation, memory preparation, and activation. Wait for the final result before using the sandbox:

<CodeGroup>
```typescript TypeScript
const creation = await Sandbox.restore("worker:snap")
    .name("resumed")
    .restoreWithProgress();

for await (const event of creation) {
    console.log(event);
}

const resumed = await creation.awaitSandbox();
```

```rust Rust
let (mut progress, task) = Sandbox::restore("worker:snap")
    .name("resumed")
    .restore_with_progress()?;

while let Some(event) = progress.recv().await {
    eprintln!("{event:?}");
}

let resumed = task.await??;
```

```python Python
creation = Sandbox.restore_with_progress(
    "worker:snap",
    name="resumed",
)

async for event in creation.progress:
    print(event)

resumed = await creation.result()
```

```go Go
events, results := m.RestoreSandboxWithProgress(
    ctx, "worker:snap", "resumed",
)

for event := range events {
    fmt.Println(event)
}

result := <-results
if result.Err != nil { return result.Err }
resumed := result.Sandbox
```

```bash CLI
# Restore shows progress by default.
msb restore worker:snap --name resumed
```
</CodeGroup>

Some stages have no percentage. Memory preparation has no fixed timeout; activation has a separate timeout. Set an overall deadline or use SDK cancellation when needed.

## Move snapshots

Archives let you move local disk or full snapshots between machines.

### Export and restore

Copy either snapshot type to another machine as a `.msb` archive. Include the image for offline restore:

<CodeGroup>
```typescript TypeScript
await Snapshot.save("baseline:ready", "ready.msb", { withImage: true });
```

## Compact disks

Merge sealed disk layers in a running or fully stopped local sandbox. This affects disk storage, including disks in full snapshots, not memory. Preview before applying:

<CodeGroup>
```typescript TypeScript
const worker = await Sandbox.get("worker");

const plan = await worker.compact({ layers: 3, dryRun: true });

const result = await worker.compact({ layers: 3 });
```

```rust Rust
let worker = Sandbox::get("worker").await?;

let plan = worker.compact().layers(3).dry_run().await?;

let result = worker.compact().layers(3).apply().await?;
```

```python Python
worker = await Sandbox.get("worker")

plan = await worker.compact(layers=3, dry_run=True)

result = await worker.compact(layers=3)
```

```go Go
worker, err := m.GetSandbox(ctx, "worker")
if err != nil { return err }

layers := uint32(3)
plan, err := worker.Compact(ctx, m.DiskCompactionOptions{
    Layers: &layers,
    DryRun: true,
})
if err != nil { return err }

result, err := worker.Compact(ctx, m.DiskCompactionOptions{Layers: &layers})
if err != nil { return err }
```

```bash CLI
msb modify worker --compact --layers 3 --dry-run
msb modify worker --compact --layers 3
```
</CodeGroup>

The default covers the root and owned data disks, excluding named/external volumes and directories. The layer limit includes the base but never the writable head; it must be at least two. Omit it to merge all sealed layers. Existing snapshots remain valid and retain storage until removed.

<Warning>
Each disk commits separately. If compaction fails, a running VM may stay paused. Restart to recover from disk journals; do not assume rollback or blindly retry.
</Warning>

Use the [SDK references](#reference) for disk selection and result fields. Do not combine compaction with unrelated modifications.

## Verify integrity

Disk content hashing is opt-in. Record hashes during capture, then verify when receiving or checking a snapshot:

<CodeGroup>
```typescript TypeScript

    .fromSandbox("baseline")
    .recordIntegrity()
    .create();

const report = await snap.verify();
```

```rust Rust
use microsandbox::Snapshot;

let snap = Snapshot::builder("deps")
    .from_sandbox("baseline")
    .record_integrity()
    .create()
    .await?;

let report = snap.verify().await?;
```

```python Python
from microsandbox import Snapshot

snap = await Snapshot.create(
    "deps",
    from_sandbox="baseline",
    record_integrity=True,
)

report = await snap.verify()
```

```go Go

    m.SnapshotCreateOptions{
        Name:            "deps",
        FromSandbox:     "baseline",
        RecordIntegrity: true,
    },
)

```

```bash CLI
msb snapshot create deps --from-sandbox baseline --integrity
msb snapshot verify baseline:deps
msb snapshot inspect baseline:deps --verify
```
</CodeGroup>

Without hashes, size and structure checks cannot detect same-length disk corruption. Save and load preserve recorded integrity but do not scan it automatically. Full-snapshot RAM has separate content-addressed checks; branch RAM is not hashed.

## Troubleshooting

| Problem | What to check |
| --- | --- |
| Cloud capture is rejected | Stop the source and use disk mode. Full snapshots and local archive options are unsupported. |
| Full restore rejects resource settings | Keep the captured CPU and memory settings, or restore with `--disk-only`. A full snapshot with a tmpfs root must resume execution. |
| A restored app loses its connection | Reconnect clients and retry application connections; live host connections are not captured. |
| Capture fails after saving a snapshot | Inspect the saved snapshot before retrying. The error may mean capture succeeded but the source could not resume. |
| A local snapshot is missing from the list | Run `msb snapshot reindex` to rebuild the local index. |
