## New features

**Explicit guest filesystem flush policies**

Snapshots, branches, and pause now accept a single `--guest-flush` policy that controls whether the guest flushes its filesystem cache for root and captured block disks before capture. `auto` (the default) requires guest writeback for live disk-only snapshots and keeps dirty pages in RAM for full snapshots and branches. `required` also flushes captured persistent filesystems, so a full snapshot can later restore its disks without RAM. `skip` accepts crash-consistent disk state. Host-backed directories, owned-directory barriers, host I/O draining, and snapshot durability are unchanged.

This is a breaking change. Owned block disks no longer force a flush during plain pause, full capture, or branching; use `required` if you depended on that.

```bash
msb snapshot create disk --from-sandbox worker
msb snapshot create full --from-sandbox worker --full --guest-flush required
msb branch worker --name child --guest-flush skip
msb pause worker --guest-flush required
```

The same policy is available from the Rust, Python, TypeScript, and Go SDKs. See [Guest filesystem flush](/sandboxes/snapshots#guest-filesystem-flush).

**Separate TCP and UDP connection limits**

Sandboxes can now cap TCP and UDP concurrency independently. `maxTcpConnections` replaces the older TCP-only setting, and `maxUdpConnections` bounds host-side UDP relay sessions. `maxConnections` remains as a deprecated TCP alias. When omitted, `single-tenant` sandboxes are unlimited and `multi-tenant` sandboxes default to 1,024 for each protocol. An explicit zero selects unlimited. At a finite UDP limit, a new session evicts the least recently active one, and sessions expire after 60 seconds of inactivity.

Legacy v0.6.x launch contracts keep their historical default of 256 TCP connections, and the SDK rejects UDP overrides against those older runtimes with an upgrade-required error.

See [Networking overview](/networking/overview#deployment-profiles).

**Administrator-managed configuration overrides**

Administrators can deploy a protected `managed.json` file to enforce settings across local and cloud backends. Managed overrides are applied after user settings and CLI or SDK options, so administrator policy takes precedence. Deploy the file to the system's protected configuration location using a device manager such as Jamf Pro or Microsoft Intune.

**Other features**

- **Runtime reliability improvements.** Completed TCP connections are reclaimed sooner, temporary files stay on disk-backed roots, and agent calls bind to the selected sandbox identity so stale objects cannot reach a replacement.

## Bug fixes

- `--guest-flush skip` now actually skips guest writeback for root and owned block disks. Auto and Required continue to require the flush, and Required capture from a pause that did not acknowledge the flush is rejected instead of silently downgrading.
- Newer SDKs and the CLI can now upgrade the catalog while older sandbox runtimes are still running. Migration locking, exclusive install coordination, transactional rollback, and incomplete-downgrade checks remain in place.
- Ordinary sandbox creation works again after upgrading from v0.6.18 to v0.7.0. Both the SDK and CLI apply their recognized catalog migrations when opening the catalog, regardless of the selected VM runtime. Selecting an older runtime does not preserve an older catalog format.
- A TLS ClientHello whose SNI contains a multi-byte character no longer aborts the sandbox process when the network policy includes a domain-suffix rule.
- On macOS, `fallocate` on a bind mount no longer truncates files that are already larger than the requested range. The passthrough backend only extends past EOF, matching the in-memory backend.
- `msb-metrics` now reads both the current v3 and legacy v2 shared-memory registries and merges snapshots by sandbox and run, preferring the newer ABI. Long-running sandboxes started against v2 continue to appear in per-sandbox metrics after a collector-only rollout.
- The network layer now forwards binary first-flight frames whose HTTP-token-like prefix contains control bytes, without applying HTTP secret substitution. Opaque traffic is still scanned for blocked placeholders.
